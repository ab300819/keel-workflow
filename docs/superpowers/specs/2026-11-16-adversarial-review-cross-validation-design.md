# adversarial-review 改为交叉验证（codex + agy）

> 2026-11-16。状态：已实施（2026-11-17，用户批准；计划见 `docs/superpowers/plans/2026-11-17-adversarial-review-cross-validation.md`）。实施时修正一处：`--print-timeout` 必须带单位（`600s`），下文命令里的 `<秒>` 以集成文档为准。

## 1. 意图

用户原话：

> 对抗审查，我希望改成交叉验证，支持 codex 和 agy，包括代码审查、独立调研等，可以对齐意见，给出最终结论

现状是「降级链」：一次只用一个外部审查方，codex 不可用才换下一个。单一审查方的结论没有参照物，协调方（宿主 Agent）只能自己逐条核实。改成两个审查方各自独立完成同一件事，再把意见对齐，能得到两类单方审查得不到的信息：两边都提的问题可信度高；只有一边提的问题提示了另一边的盲区。

## 2. 目标、非目标、反目标

**目标**

- 交互调用 `/adversarial-review` 时，先问用户要双方共同审查还是单方审查；选双方时把同一份 brief 同时发给 codex 和 agy，互相不可见。
- 代码审查、方案/文档审查、独立出方案、独立调研四类任务都走这一套。
- 把两边的意见合并成一份对齐表，给出一个最终结论。
- 一方不可用时退回单方，并在结论里明说。

**非目标**

- 不改 skill 名（9 个文件引用它，改名无收益）。
- dev-workflow 内嵌的自动审查（embedded-headless）不变，仍只用 codex 的 T1/T2；`ext_review_state` 枚举不变。
- 不接 ACP（仍搁置，见 `external-reviewer-integration.md` 概述里的记录）。
- 不做「可插拔审查方框架」。审查方就是一张两行的表，第三家出现时再加一行。

**反目标**（技术上能跑但算失败）

- 用「两票对一票」代替证据。两边一致只提高可信度，不免除协调方用代码/文档驳回的权利。
- 成本失控。轮次上限、熔断规则不放宽；一轮 = 一次并行调度，不是两轮。
- 一方失败被静默吞掉，结论看起来像双方审过。

## 3. 约束

- `SKILL.md` ≤ 500 行（现 453 行）。新增规则细节放 `references/`，正文只留流程与硬约束。
- 共享规格用工具无关表述。审查方的具体命令只出现在 `references/external-reviewer-integration.md`。
- 现有安全门对每个审查方分别生效：截断不是审查结果、失败先分类再路由、降到同模型子 Agent 必须标注折损。「额度耗尽报告并停下」有一处有意的收窄，见 5.5。
- 独立性：agy 可选的模型里有与宿主同族的。⛔ agy 用的模型不得与宿主 Agent 同族，也不得与 codex 同族，否则「交叉」退化成自审。

## 4. 考虑过的做法

| 做法 | 内容 | 取舍 |
|---|---|---|
| **A 并行独立 + 协调方对齐（选定）** | 同一 brief 并行发给两方，各自独立输出，协调方合并对齐 | 独立性最强；成本约为单方的两倍 |
| B 串行互审 | codex 先审，agy 再审 codex 的发现 | 便宜一些，但第二方被第一方的结论锚定，只能发现「第一方说错了」，发现不了「第一方漏了」 |
| C 只把 agy 加进降级链 | codex 不可用时换 agy | 改动最小，但仍是一次一方，不满足「对齐意见」 |

用户选定 A，并确认了四项：交互调用时显式询问用户选双方还是单方（原定「默认双方」，用户于 2026-11-16 改为询问）；不改名；dev-workflow 内嵌审查先不用双方；两方矛盾且核不清时交用户裁定。

## 5. 设计

### 5.1 审查方

| 审查方 | 通道 | 备用 |
|---|---|---|
| codex | 现有 T1（CLI）| 现有 T1b（备用计费后端）、T2（codex-mcp），规则不变 |
| agy | `agy` CLI 非交互模式 | 无 |

现有 T3（同模型子 Agent）保留，只在**两个外部审查方都不可用**且用户同意时作为兜底，折损标注规则不变。

agy 调用形态（2026-11-16 本机 1.5.7 实测通过）：

```bash
# 文本类（方案/文档审查、独立方案、独立调研）
agy -p "<brief>" --mode plan --sandbox --model <非宿主同族模型> --print-timeout <秒> < /dev/null

# 代码审查（结构化）
agy -p "<brief>" --mode plan --sandbox --model <…> --print-timeout <秒> \
    --output-format json --json-schema references/review-output.schema.json < /dev/null
```

实测得到的三条事实，实施时必须写进集成文档：

- ⛔ brief 走命令行参数时，标准输入必须关闭（`< /dev/null`）。codex 同理：本仓实测一次 `codex exec` 用参数传 brief 却没关标准输入，挂起 18 分钟没开始工作。codex 现有「用标准输入传长 brief」的路径不受影响——那条路径读完 brief 自然收到结束信号，⛔ 不得给它加 `< /dev/null`。
- 结构化输出包在外层 JSON 的 `response` 字段里，且该字段在 JSON 之前**带有过程叙述文字**。解析时取 `response` 中最后一个完整的顶层 JSON 对象，再按 schema 校验；取不到或校验不过按现有「截断 / 格式异常」规则分流。
- `--mode plan --sandbox` 下没有写入工作区（实测后 `git status` 干净）。

默认模型：`agy models` 列表中非宿主同族、非 codex 同族的最高档（本机当前为 Gemini 4 系列）。用户口头指定时以用户为准。**本条是我的决定，不是用户定的。**

### 5.2 流程变化

```
S1 上下文收集 → S2 构建 brief（不变）
  → S2.5 询问审查方式：双方 / 只 codex / 只 agy
  → S3 调度：选双方时同一 brief 并行发给两方，各自走自己的通道与失败分类
  → S4 原样展示：两方的完整原始输出分别展示，不合并、不过滤
  → S4.5 对齐：合并成一份发现列表，每条标来源
  → S5 逐条验证（按来源分别处理，见 5.3）
  → S6 用户确认 → 最终结论
```

**S2.5 询问审查方式**（用户要求）：调度前用 AskUserQuestion 问一次，三个选项各带后果：

| 选项 | 后果 |
|---|---|
| 双方共同审查 | 两方独立审、意见对齐后出结论；外部调用量约翻倍，耗时取较慢一方 |
| 只用 codex | 与改造前相同；没有第二方参照 |
| 只用 agy | 单方；codex 额度紧张时可用 |

- 每次审查会话只问一次，复审轮次沿用首轮的选择，不重复问。
- 用户在请求里已经说明的不再问：「交叉验证」「两边都审」→ 双方；「让 codex 审」「只用 agy」→ 对应单方。
- 探测发现某一方本机不可用时，不列出含该方的选项，并说明原因；只剩一方可用时不问，直接单方并告知。
- 选单方时走单方流程，跳过 S4.5，摘要 `single_reviewer: true`，`reviewers[]` 里另一方记 `status: skipped`、`reason: user_choice`。
- 仅适用于交互调用。无法提问的场景（作为子 Agent 被调度）按调用方传入的选择执行，未传入则用单方 codex——与改造前行为一致。**最后这条默认值是我的决定。**

**复审轮次**：沿用首轮的选择；选了双方的，下一轮仍并行发给两方。**我的决定**：保持每轮口径一致，否则健康分跨轮不可比。

### 5.3 对齐规则（S4.5 + S5）

合并时判断两条发现是否为同一问题：位置相同或重叠，且描述的是同一个缺陷。沿用现有「跨轮问题关联」的语义匹配做法，不新造算法。合并后重新编号 F-001…，每条带来源：

| 来源 | 含义 | S5 处置 |
|---|---|---|
| `both` | 两方都提了 | 与单方来源走**同一套完整验证**（事实核查 → 上下文检查 → 判定 → 严重程度由验证方定）。来源只作为信息展示，⛔ 不降低验证要求：两方可能共同误解同一条约束 |
| `codex` / `agy` | 只有一方提 | 走现有完整验证（事实核查 → 上下文检查 → 判定），成立才确认 |
| `conflict` | 两方对同一处给出相反判断（一方说有问题、另一方明确说没问题，或修复方向互斥）| 协调方核对事实后判定并附证据；核不清的 ⛔ 不得自行拍板，列入 S6 交用户裁定 |

来源的用处在展示与排序：对齐表里 `both` 排在前面，并提示用户「两方独立得出」；`codex` / `agy` 单方来源提示另一方的盲区。

一方沉默不算 `conflict`，算单方来源。只有另一方对同一处**明确表态相反**才算冲突。

健康分、收敛检测、熔断在合并后的列表上计算，公式不变。

### 5.4 独立出方案 / 独立调研

反锚定规则不变：brief 只给用户原话与硬约束，不给我方方案。两方收到同一份 brief。消费时的对照表由三列变四列：

| 议题 | codex | agy | 我方 | 核实结论（附证据） |
|---|---|---|---|---|

只列有分歧的议题。两个第三方一致而与我方不同的，单独标出——这是最值得用户看的一类。

### 5.5 一方失败

每个审查方独立套用现有失败分类与截断判定。

| 情况 | 处置 |
|---|---|
| 一方成功、一方失败或截断 | 用成功一方的结果走单方流程；结论首行写明「本轮只有 <某方>，<另一方> 因 <原因> 未完成」；摘要 `single_reviewer: true` |
| codex 额度耗尽 | 先按现有规则试 T1b。T1b 也不可用时：**agy 成功则不停下**，按上一行继续，并在结论首行照抄已耗尽的通道与重置时间；agy 也未成功才停下 |
| 两方都未成功 | 按现有「额度耗尽的默认行为」报告并停下，由用户决定等待 / 降 T3 / 换后端 |
| 一方截断 | ⛔ 截断方的输出不进入对齐，不计为「该方没意见」 |

**对现有规则的有意收窄（我的决定，请用户确认）**：现役规则是「codex 额度耗尽且 T1b 不可用 → 一律停下等用户」，理由是当时的下一步只有降到同模型子 Agent，属于真实的检出率损失。现在另一个**外部**审查方若已成功，继续不会降到同模型，所以不停下，只如实标明单方。停下门只在「没有任何外部审查方成功」时触发。

### 5.6 最终结论与摘要

最终报告在现有模板基础上增加一张对齐表（编号 / 问题 / 来源 / 判定 / 证据）和一句总裁决。

yaml-summary-v1 的 `details` 新增下列字段。现有字段的含义按下表调整（本 skill 之外没有消费方读 `review_method` / `primary_method` / `truncated`，已 grep 确认）：

| 现有字段 | 调整后含义 |
|---|---|
| `review_method` | 两方都成功填 `cross`；只有一方成功填该方实际通道（枚举增加 `agy-cli`）|
| `primary_method` | 不变，仍只描述 codex 一侧首次探测锁定的通道 |
| `truncated` | 只在**本轮没有任何一方给出完整结果**时为 `true`（含义仍是「findings 不可信」）。单方截断、另一方成功时为 `false`，截断记在 `reviewers[].status` |
| `quota_exhausted` / `reset_hint` | 任一方遇到额度耗尽即如实填写，不论另一方是否成功 |
| `degraded_detection` | 不变，只在实际走了同模型子 Agent 时为 `true` |

```yaml
reviewers:                    # 每个审查方一项
  - name: codex | agy
    method: codex-cli | codex-cli-alt | codex-mcp | agy-cli
    status: ok | failed | truncated | skipped
    reason: null              # 失败 / 跳过原因
single_reviewer: false        # true = 本轮实际只有一方（含用户指定）
agreement:                    # 合并后各来源的条数
  both: 0
  single_source: 0
  conflict: 0
  unresolved_conflict: 0      # 交用户裁定的条数
```

### 5.7 顺带澄清：审查循环里「谁来改」

现文只说「输出修复建议（skill 不直接修改文件）→ 重新提交审查」，没说谁改。补一句：用户接受修复方案后，由宿主 Agent 在本 skill 之外实施修改，改完再发起下一轮；本 skill 自始至终只读。

## 7. 验证

- 冒烟：两个审查方各自的检测步骤都含一次真实工具调用（沿用现有要求）。
- 真跑一次代码审查：对本仓一个小 diff 走完整流程，产出含对齐表的结论；检查三种来源至少出现两种，或如实记录只出现一种。
- 真跑一次独立调研：确认两方 brief 相同且不含我方方案。
- 询问：不带倾向地调用一次，确认会问且三个选项带后果；请求里写明「只用 codex」再调用一次，确认不问。
- 一方失败：故意给 agy 一个不存在的模型名，确认结论首行标明单方、摘要 `single_reviewer: true`。
- `health-lint.py --skills-dir skills` 0 blocker；`SKILL.md` 行数 ≤ 500；`git diff --check`。
- 未能验证的如实写明：codex 额度耗尽与截断路径无法按需复现，只做规则走查。
