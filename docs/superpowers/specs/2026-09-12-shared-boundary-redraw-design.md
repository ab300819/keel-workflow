# 共享边界重划

## 0. 为什么这是第 1 步

两套开发模式并行、共享 SSOT。**模式 B 动笔前必须先知道自己能依赖什么。**

⇒ 本步只做一件事：**给 `constraints.md` 的每条规则确定适用域。** ⛔ 不改规则内容、⛔ 不新增规则、⛔ 不动对象模型。

### 0.1 v1 的数据全部作废

外部审查逐项复算后，v1 的分类与计数不成立。**本版所有数字用「定义位判别」重新提取**（见 §1.1），并逐条列出证据。

| v1 声称 | 实测 |
|---|---|
| 138 条规则 | **131 个定义**。138 是含**引用**的反引号字符串去重数 |
| 3 条 A 私有 | **0 条**。三条全是模式中立（§2.1）|
| §4 十二类合计 110 | 实际 **17 个命名空间 / 131 条**，v1 漏了 4 个命名空间 |

> **v1 错在同一个地方**：用「反引号里有 `x/y` 形态」当定义、用「点名了 `ms-*`」当 A 私有——**两次都是形态匹配代替语义核实**。

## 1. 实测

### 1.1 判别方法（⛔ 不是形态匹配）

**定义** = `rule_id` 出现在列表项 / 表格行 / 标题的**主语位**：

```
- `gate/two-senses`：…          ← 定义
| `yaml-summary/skill-name` | … ← 定义
> 本条取代原 `doc/status-extraction`（…）  ← 引用，⛔ 不是定义
```

按此判别：

| 口径 | 数 |
|---|---:|
| **定义** | **131** |
| ├ 行首主语位 | 130 |
| └ 粘在上一行末尾（`:165` `task/blocker-propagation`）| 1 |
| 纯引用、⛔ 无定义 | 7 |
| 反引号字符串去重（v1 用的口径）| 138 |

**7 个纯引用**：`doc/status-extraction`（被取代的旧规则）· `state/total-size-cap` · `state/line-length-cap` · `state/max-id-stale` · `design/adr-only-revision` · `health/dead-link` · `id/unknown-prefix`（后六个是 health-lint 的规则，在本文只被引用）。

> ⚠️ **顺带发现一处排版缺陷**：`constraints.md:165` 的 `task/blocker-propagation` 粘在上一个列表项末尾（缺换行）。任何行首扫描都会漏掉它。**建议本步一并修**。

**131 条全部是共享规则。** 其中 6 条需要额外标记：

## 3. 标注机制

### 3.1 默认共享，只标例外

125 条共享规则 ⛔ 不加标记。只标：

| 标记 | 用在哪 | 数量 |
|---|---|---:|
| `[scope:A]` | §2.4 的 4 个对象模型章节 | 4 |
| `[pending:C]` | §2.2 的 3 条 | 3 |
| `[consumers:pending-B]` | §2.3 的 3 条规则 + 1 章节 | 4 |

⛔ **不设 `[scope:B]`**——B 的规则应住在 B 的 skill 里，进共享层需另走准入（§3.2）。
⛔ **不设 `[scope:A+B]`**——等于无标记。

### 3.2 新增规则的准入（追加到 `doc/two-kinds` 的三条之后）

> 4. **声明适用域** —— 新增规则必须能回答"模式 B 下这条还成立吗"。判据是**该规则约束的行为本身是否与开发类型有关**，⛔ 不是"它提到了哪个 skill"。答不出的 ⛔ 不得进本文，退回该模式的 skill。

> 判据的措辞是本轮教训的直接产物：v1 用"点名了 `ms-*`"作判据，三条全判错。

## 4. 模式 B 可以依赖什么

**131 条定义分布在 17 个命名空间**（实测）：

| 命名空间 | 定义数 | | 命名空间 | 定义数 |
|---|---:|---|---|---:|
| `realign` | 19 | | `readonly` | 6 |
| `yaml-summary` | 15 | | `doc` | 5 |
| `task` | 16 | | `dry-run` | 4 |
| `confirm` | 13 | | `layered-memory` | 4 |
| `gate` | 10 | | `workspace` | 4 |
| `recovery` | 10 | | `skip` | 3 |
| `scope` | 8 | | `enum` | 3 |
| `future` | 7 | | `id` | 2 |
| | | | `diff` | 2 |

> ⚠️ v1 的表列了 12 类合计 110，**漏了 `doc`(5) / `future`(7) / `skip`(3) / `diff`(2) 四个命名空间**，且 5 类计数有误。本表按 §1.1 判别法实测。

**其中三条对 B 特别关键**：

- `scope/gate-coverage`「评审边界 ≥ 影响边界」——B 的完成门天然影响面导向
- `confirm/scope-inflation`「改动面超诉求一个数量级必须停」——重构最易失控处
- `id/prefix-consumption-contract`——`CHG` 按它登记，⛔ 不需要为 B 新开登记机制

⚠️ **但 `id/prefix-consumption-contract` 的正文仍规定「行为需求走 `F+AC`、非编码需求走 `CON`」**——那是 A 的路由。补消费方枚举**不够**，还要说清它与 `CHG` 路由的关系。⇒ 归第 2 步处理。
