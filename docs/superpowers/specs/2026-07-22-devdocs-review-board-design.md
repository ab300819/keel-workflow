# DevDocs 可视化评审面板(ms-board)设计方案

- **日期**:2026-07-22
- **状态**:**已定稿**(codex 6 轮对抗审查,R6 PASS 无发现)
- **作者**:Mason + Claude
- **相关**:[DevDocs 重定位](../../../docs/workflows.md)、[constraints.md](../../../skills/_shared/constraints.md)

## 1. 背景与问题

DevDocs 的定位是**代码=SSOT、文档=决策记忆层(why)+追溯索引**。文档结构(编号体系、门控标记、契约表)为 AI 消费和追溯链路优化,不为人的线性阅读优化——这是刻意取舍,但代价是**视图层缺失**:人评审 01-requirements / 02-system-design 时只能裸读 Markdown,认知负担高,评审质量依赖读者毅力。

目标:提供**可视化 + 可交互的评审页面**,作为用户与 Agent 之间的沟通桥——用户在页面上勾选/输入评审意见,Agent 能感知并响应,最终意见回流为文档修订。

评审对象(v1):**01-requirements + 02-system-design 文档集合**(含拆分文件,见 §6 source manifest)。

## 2. 定位红线(架构不变量)

1. **页面 = 视图 + 意见收集器,绝不是第二个 SSOT**。页面内容由 01/02 单向派生生成;页面上的勾选/输入是"评审意见",不是文档状态。
2. **意见回流必须经 Agent 转化为文档修订**,走 §4.1 评审修订协议(编号不变/矩阵同步/下游影响清单)。页面不直接写任何文档。
3. **生成物不入库**:board HTML 写入系统临时目录,可随时从源文档重建。评审的持久痕迹只存在于两处——文档修订本身 + 02 §设计审查表的评审结论登记。
4. **浏览器安全纪律**:chrome-devtools MCP 连接的是用户真实浏览器(含其他敏感标签页)。每次生成分配随机 `board_id`(嵌入文件名与 `<html data-board-id>`);所有 `evaluate_script` **脚本内部先自校验** `document.documentElement.dataset.boardId` 与预期一致,失配立即返回错误、不触碰任何 DOM/状态(**fail-closed**,降级 §8 T2)。读仅限 `window.__review`,写仅限 `id` 前缀为 `agent-` 的节点;严禁对任何其他标签页执行脚本。
5. **零远程依赖**:页面完全自包含,`<meta http-equiv="Content-Security-Policy">` 禁止一切外联(`default-src 'none'` + 必要的 `'unsafe-inline'` 样式/脚本例外 + **`img-src data:`**——放行自身内嵌 SVG 图,其余外联一律禁止)。01/02 内容可能含商业敏感信息,不得经任何 CDN/网络泄出。

## 3. 方案概览

**新增独立 skill:`ms-board`**(目录 `skills/board/`),职责 = 生成器 + 感知协调器。

组件:

| 组件 | 位置 | 职责 |
|------|------|------|
| SKILL.md | `skills/board/SKILL.md` | 流程编排(S1~S7)、约束、协作 |
| board-protocol.md | `skills/board/references/` | review-state-v1 schema、感知/安全纪律、评审修订协议(§4.1)、T2 传输 schema |
| board-template.html | `skills/board/templates/` | 自包含 HTML 骨架(样式/交互 JS/state 管理),生成时注入解析数据 |

数据流(单向派生 + 意见回流):

```
01/02 文档集合 ──解析──> 评审项数据(内嵌 HTML) ──用户操作──> window.__review
    ↑                                                          │ evaluate_script 读回(脚本内自校验 board_id)
    └── 文档修订(§4.1 协议) <── AskUserQuestion 确认 <── Agent 逐条转化 ┘
                    (Agent 响应经 evaluate_script 写回页面 agent-* 节点)
```

桥:**chrome-devtools MCP**(`new_page` / `list_pages` / `select_page` / `evaluate_script`)。已于 2026-07-22 冒烟实证:file:// 页面可打开,双向读写(读 `window.__review` / 写 DOM)均通。

**内容注入安全**:所有源文档内容经 **HTML-safe JSON 序列化**嵌入(`<script type="application/json">` + `JSON.parse`;序列化时 `<` 一律转义为 `\u003c`、`>` 为 `\u003e`、行分隔符 U+2028/U+2029 同转义——防 `</script>` 闭合数据标签后注入;或等价采用 base64 容器),渲染一律 `textContent`(或等价安全构造),**禁止 `innerHTML` 承载文档内容**——防止文档内嵌脚本在页面执行。

**架构图渲染**:生成时探测本地 `mmdc`(mermaid-cli):可用则把 02 的 mermaid 源码渲染为 SVG,并以 **data-URL `<img>`** 方式内嵌(`<img src="data:image/svg+xml;base64,...">`——img 上下文不执行脚本、不加载外部资源,SVG 产物视为不可信输入的天然沙箱);渲染失败或 `mmdc` 不可用则显示语法高亮源码块 + ℹ️ 提示。**禁止将 SVG 作为标记直接插入 DOM**;不加载远程 mermaid(红线 5)。

**渲染阶段网络边界**(mermaid 源码视为不可信输入):`mmdc` 以 headless 浏览器渲染,mermaid 自身无可配置的外部资源阻断(strict 级仅编码 HTML/禁点击),图内 image/外链指令可在**渲染期间**发起外联。因此**网络 deny-all 隔离是渲染的必要条件**:仅当能将渲染进程置于拒绝一切网络访问的环境(如 macOS `sandbox-exec` 拒网 profile 或等价机制)时才调用 `mmdc`;**无法提供网络隔离 → 一律不渲染,直接回退源码块**。渲染前的外链指令扫描(image、URL、`click`/`href`、CSS `url()` 等模式,命中即先行回退)仅作**纵深防御**,不作为安全边界。验收须验证渲染期间无外联,而非仅验证最终 `<img>` 不外联。

## 4. 用户流程

```
/ms-board [--scope=01|02|all]   # 默认 all
```

- **S1 前置检查**:01 主文件必须存在(⛔ 缺失则提示先走 ms-requirements);02 可选(缺失则仅评 01,ℹ️ 提示)。探测 chrome-devtools MCP 可用性,不可用走 §8 降级。
- **S2 解析生成**:按 glob `01-requirements*.md` / `02-system-design*.md` 收集**文档集合**,逐文件记录**内容 hash(sha256)**构成 source manifest;提取结构化评审项(§5 模型);分配随机 `board_id`;渲染 HTML 到临时目录(文件名含 board_id);`new_page(file://...)` 打开。
- **S3 用户评审**:用户在页面上逐条勾选(通过/不通过/搁置)+ 输入意见。状态同步写入 `sessionStorage`(键含 board_id),刷新可恢复;未提交时 `beforeunload` 离页提示。Agent 不轮询、不阻塞。
- **S4 感知触发**:用户在对话中示意"评完了"(页面"提交评审"按钮仅置 `submitted=true` 作核对用)→ Agent `list_pages` 按 board 文件 URL 匹配 → `select_page` → `evaluate_script`(脚本内自校验 board_id,失配 fail-closed → T2)读回完整 `window.__review`。
- **S5 逐条转化**:校验 source manifest 全部文件当前 hash,任一失配 **⛔ 阻断**(评审基于过期版本)→ 重新生成后重评(sessionStorage 中稳定编号锚的意见可迁移,迁移后需用户重新确认)。每条意见 → 具体文档修改建议(引用章节/编号),AskUserQuestion 批量确认(接受/调整/驳回)。
- **S6 回写**:按 §4.1 评审修订协议 + §4.2 批次写入协议执行。
- **S7 页面回应**:`evaluate_script`(同样自校验)把每条处理结果(已采纳/已驳回 + 理由)写回页面对应条目的 `agent-*` 栏;成功闭环后清除该 board 的 sessionStorage。

### 4.1 评审修订协议(回写规则)

| 意见类型 | 回写方式 | 一致性保障 |
|----------|----------|------------|
| 修改既有条目(F/US/AC/接口/模块等) | 直接修订正文,**编号不变**;01 修订记录统一落**所属 F 行的"变更历史"列**(唯一有该列的表),格式 `评审修订(<条目号>) <日期>`,US/AC 表结构零改动 | 修订后校验追溯矩阵与正文一致(F→US→AC 链无断链),矩阵同步更新 |
| 01 章节级修订(NFR/范围/风险等,无所属 F) | 能关联受影响 F 则登记该 F 行变更历史;**确无关联 F** 时在被修订章节末尾追加一行 `> 评审修订 <日期>:<变更摘要>`(格式定义于 board-protocol.md,零模板改动) | 修订痕迹不丢失 |
| 新增条目 | **委托 `/ms-requirements` 增量模式**(现成能力:编号续编、矩阵更新、原始需求登记) | 由 ms-requirements 自身约束保障 |
| 删除条目 | **标废弃不物理删**(状态列/前缀标注),保留编号占位 | 追溯链不断裂;物理清理属 ms-sync/close 职责 |
| 02 设计变更 | 走现有**增量设计流程**(影响分析 → 正文修订 → 涉决策补 ADR,规则见 system-design references/incremental-design.md) | ADR 与正文同步(adr-only-revision 规则兜底) |
| 评审结论登记 | 02 §设计审查表逐条记录(视角/挑战/回应/结论);01 无评审节,不新增(YAGNI) | — |
| 下游影响 | 03/04 已存在且本次修订触及其依赖内容 → 产出**"待同步影响"ℹ️ 清单**(条目+建议入口,如 /ms-sync 或 /ms-test-cases),不自动改 03/04 | 不阻塞,由用户决定时机 |

### 4.2 批次写入协议(S6 一致性保障)

一次回写通常触及多个文件(正文/矩阵/ADR/审查表)。文件系统无跨文件事务、也无原子 compare-and-write,本协议是**尽力检测已观测到冲突的协议**——承诺:各校验点观测到的冲突必被报告、写入状态必被如实呈现;**不承诺**检出比对与写入之间窗口(TOCTOU)内的并发修改。边界声明:S6 执行期间 Agent 是预期唯一写者(solo 场景),窗口内用户手改属已声明的残余风险;需要更强保证时的受控单写者/协作锁机制 = FUTURE(触发:多写者真实场景出现)。

1. **全量预检**:写入任何文件前,校验本批**全部**目标文件当前 hash 与期望 hash 一致,任一失配 ⛔ 整批中止(此时零写入,状态干净)。
2. **写入计划**:列出目标文件 × 修改点,按依赖顺序(正文 → 矩阵/审查表)执行。
3. **逐文件写前复核**:每个文件**写前**重新比对当前 hash 与期望 hash(缩小"预检后、写入前"窗口,非原子保证),写入后立即读回验证,并**更新该文件的期望 hash**(自写变更不算冲突)。
4. **终核**:本批全部写完后、S7 闭环前,对全部目标文件做一次**全量复核**(当前 hash == 各自最新期望 hash),通过才允许 S7。
5. **任一环节失配**(外部并发修改):立即停止后续写入,报告**已写/未写清单**;S7 **不得闭环**(页面不标"已采纳");恢复路径 = 未写部分基于新文档状态重走 S5 确认。已写文件不自动回滚(修订本身经过确认,回滚反而丢确认过的内容),由报告 + 用户决策处置。

## 5. 评审项模型(页面信息架构)

**01 需求评审**:

| 评审单元 | 粒度 | 呈现 |
|----------|------|------|
| F-XXX 功能点 | 逐行 | 表格 + 三态 + 意见框 |
| US-XXX 用户故事 | 逐行 | 同上 |
| AC-XXX 验收标准(核心单元) | 逐条 | 三态 + 意见框;缺"验证方式"自动高亮 |
| 追溯链 F→US→AC | 整体 | 自绘树/嵌套列表(无外部库),点击跳转对应评审项 |
| 背景/目标 ↔ 原始需求一致性 | 章节级 1 条 | 并排呈现"原始需求"(§0)与"背景与目标"(§1),三态 + 意见框 |
| 设计资产(§0.5,存在时) | 章节级 1 条 | 三态 + 意见框 |
| 非功能性需求(§6)/ 范围边界(§7) | 各 1 条章节级 | 三态 + 意见框 |
| 风险与假设(§8) | 章节级 1 条 | 三态 + 意见框 |

**02 设计评审**:

| 评审单元 | 粒度 | 呈现 |
|----------|------|------|
| 架构图(§2 mermaid) | 整体 | 本地 mmdc → SVG 内嵌;无 mmdc 显示源码块(§3) |
| 模块表(§4) | 逐模块 | 三态 + 意见框 |
| 核心接口(§5) | 逐接口 | 契约表折叠展开 + 三态 + 意见框 |
| ADR | 逐条 | 三态 + 意见框 |
| 其余实质章节:目标平台(§1)/技术选型(§3)/设计模式(§6)/代码落位原则(§7)/数据模型(§8)/API 设计(§9)/状态流转(§10)/异常处理(§11)/日志设计(§12)/扩展性(§13) | 各 1 条章节级(**章节存在才生成**,含拆分文件中的章节) | 内容摘要 + 三态 + 意见框 |
| 需求追溯(§14) | 整体 | 覆盖缺口**自动高亮**:01 的 F/US/AC 编号集 对比追溯表的模块/接口/数据实体映射,缺失行标红(纯视图计算,不改文档) |

**全局**:进度条(已评 x/y)、"只看未评审"过滤器、提交按钮、全局意见框。

> 粒度原则(YAGNI):编号对象(F/US/AC/接口/模块/ADR)= 细粒度逐条;其余实质章节 = 章节级一条,避免评审项爆炸。
>
> **解析规则(标题驱动)**:章节识别按**标题文本匹配**,不硬编码章节号(模板与 SKILL.md 权威清单存在编号漂移,且历史项目格式不一;上表编号仅为示意,权威 = 01 requirements-template / 02 system-design SKILL.md「文档结构」16 节)。匹配基于 board-protocol.md 维护的 **canonical-title/别名表**(如 目标平台↔运行平台、扩展性↔扩展性设计),标题规范化(去编号/空白)后先精确匹配 canonical 或别名,未命中才落"其他章节";别名表以现行模板 + SKILL.md 权威清单双源初始化,验收样例须覆盖标准模板主文件与拆分文件。**完整性规则**:凡未被细粒度单元覆盖、且内容非空的实质章节,一律自动生成章节级评审项;页面顶部展示**覆盖映射**(已生成评审项的章节清单 + 有意排除项及理由,如"§设计审查/§ADR 历史记录不评审"),消除"页面已覆盖全部文档"的假象。无法识别归类的章节归入"其他章节"评审项并 ℹ️ 标注。

## 6. review-state-v1(页面状态 schema)

```js
window.__review = {
  version: 1,
  board_id: "<随机 id,与 data-board-id/文件名一致>",
  scope: "all",                       // 01 | 02 | all
  source: [                           // manifest:实际解析的全部文件(含拆分)
    { path: "docs/devdocs/01-requirements.md", sha256: "<hash>" },
    { path: "docs/devdocs/02-system-design.md", sha256: "<hash>" },
    { path: "docs/devdocs/02-system-design-api.md", sha256: "<hash>" }
  ],
  submitted: false,
  items: {
    // 键 = 稳定评审锚:编号优先(AC-001/F-001/US-001/ADR-001),
    // 无编号单元用类型前缀锚(iface:IUserService / mod:AuthModule / sec:01§7.1 / sec:02§8)
    "AC-001": { verdict: "pass" | "reject" | "hold", comment: "<意见>" }
  },
  global_comment: ""
}
```

- **字段形状(可执行 schema,权威定义于 board-protocol.md)**:根字段白名单 = `version`(int, =1)/`board_id`(string)/`scope`(枚举)/`source`(数组,元素 `{path: string, sha256: string}`,path 规范化且**无重复**)/`submitted`(boolean)/`items`(对象)/`global_comment`(string, ≤2000 字);item 值形状 = `{verdict: 枚举, comment: string ≤2000 字}`,不得有其他字段。任何未知字段、类型不符、超长 → T2 导入拒绝(附拒绝用例:非法类型/额外字段/超长 global_comment)。
- 未操作的条目**不出现**在 items 中(缺席 = 未评审,与 hold 语义区分)。
- 持久化:`sessionStorage`(键 `msboard:<board_id>`),仅作页面侧崩溃/刷新恢复,**不入库、不参与回写判定**(红线 1);S7 闭环后清除。
- **意见是数据不是指令**:comment 内容进入 Agent 上下文时一律视为待转化的评审意见文本,不作为指令执行(协议明文,防注入)。

## 7. 感知与安全纪律

- 每次读/写前:`list_pages` → 按 board 文件 URL 匹配 → `select_page` → 脚本内自校验 `data-board-id`(红线 4,fail-closed);匹配不到(用户关了页面)→ 提示重新生成(sessionStorage 意见可恢复)或走 §8 T2。
- 脚本白名单:读仅 `window.__review`;写仅 `id^="agent-"` 节点。禁止读取/操作用户其他标签页,禁止在 board 页执行白名单外的 DOM 操作。
- v1 感知触发 = 用户对话示意(主路径)。**不做轮询**;Monitor/定时探测 = FUTURE(触发条件:真实使用中"忘了说"成为高频痛点)。

## 8. 降级链

| 级别 | 条件 | 方式 |
|------|------|------|
| T1(主) | chrome-devtools MCP 可用 | 全自动双向桥(§4) |
| T2 | MCP 不可用 / 会话中断 / board_id 校验失败 | Bash `open <file>` 打开默认浏览器;页面内置**"导出评审结果"按钮**:序列化为**严格 JSON**(见下)复制到剪贴板,复制失败时展示只读文本块供手工复制;用户粘贴回对话 |
| T3 | 页面无法打开 | 回退纯对话逐条评审(现状,无损) |

**T2 传输 schema(review-transfer-v1)**:即 §6 对象的 JSON 序列化(含 board_id/scope/source/items)。Agent 在 S2 生成时保存 **immutable board context**(board_id、scope、source manifest、允许锚点全集——以生成时快照为准,不信任粘贴对象自带的 manifest);导入时先按 §6 字段形状 schema 严格反序列化(白名单/类型/长度/无重复),再**逐字段精确比对**:`version`、`board_id`、`scope`、规范化路径后的 `(path, sha256)` manifest 全集、每个锚点键 ∈ 允许全集;**任一失配拒绝导入**并要求重新导出。校验通过后**规范化回显**(n 条意见 × 摘要)由用户确认再进 S5。两条路径产出同一 schema,S5 起流程合流。

## 11. 验收标准

1. `/ms-board` 在存在 01(含或不含 02、含拆分文件)的项目中能生成并打开页面;缺 01 主文件 ⛔ 明确提示。
2. 页面**零远程依赖**、离线可评审;含 CSP(显式 `img-src data:`,内嵌 SVG 正常显示);文档内容经 HTML-safe 序列化注入,构造含 `<script>` 或 `</script><script>…`(闭合数据标签)的 AC 描述均不会在页面执行;**mermaid 渲染仅在网络 deny-all 隔离环境中执行(无隔离能力一律回退源码块,渲染期间零外联;外链源码另被扫描先行拦截作纵深防御),渲染产物(data-URL img)不执行脚本、不发起外联**,渲染失败回退源码块。
3. 用户勾选/输入后,Agent 经 T1 桥能读回完整且合法的 review-state-v1;读写脚本在 board_id 失配时 fail-closed(不触碰 DOM、报错降级)。
4. 每条意见转化为引用具体章节/编号的修改建议,经确认后按 §4.1 协议回写:编号不变、修订记录落所属 F 行变更历史列、矩阵同步、新增走 ms-requirements 增量、删除标废弃、02 评审结论落 §设计审查表、下游影响清单产出。
5. 批次写入满足 §4.2:全量预检失配零写入;逐文件**写前复核**尽力检测该时点已观测到的失配(非原子保证,比对-写入窗口内的修改为已声明残余风险);S7 前全量终核,任一观测到的失配停止后续写入、报告已写/未写清单、S7 不闭环;自写变更正确更新期望 hash 不误报冲突。
6. Agent 处理结果能写回页面对应条目(S7 闭环);页面刷新后评审状态从 sessionStorage 恢复。
7. T2 路径:导出 JSON → 粘贴 → 严格 schema 校验(非法类型/额外字段/超长 global_comment 均拒绝)+ 与 immutable board context 逐字段精确比对(board_id/scope/manifest/锚点全集),失配拒绝;通过后规范化回显确认 → 完成同等评审闭环。
8. 章节覆盖:标题驱动解析对 01/02(含拆分文件)生成的评审项满足完整性规则;页面顶部覆盖映射与实际文档章节一致,无静默遗漏。
