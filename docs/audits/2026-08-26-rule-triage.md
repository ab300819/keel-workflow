## 分类中浮现的保留类型

| 类型 | 判据 | 例 |
|---|---|---|
| **K1 纠偏护栏** | 对抗模型的稳定倾向 | 测试不可变、信息屏障、断言数量不得减少、标注不得删减、排除 skipped/todo、声称 vs 实际 diff 交叉验证、`dev-tasks:234` 禁止从实现反推测试 |
| **K2 项目约定 / schema** | 模型无从知道 | 编号体系、文件路径、状态名、commit 尾注、拓扑分支 |
| **K3 安全 / 授权** | 后果不可逆或越权 | 绝不推送远程、工作区洁净、detached HEAD 门、敏感数据不明文 |
| **K4 确认点** | 需要人的判断 | 方案确认、不相关变更警告、旧任务处置 |

> K1 是这套体系的真正资产。`dev-tasks:234`「测试断言必须引用 AC，**禁止从实现代码反推测试**」与已废弃的 retrofit 逆向推导是同一个缺陷的两面——一个反着推需求，一个反着推测试，都产生必然自洽的假证据。
