# TAR 原则评估标准（TAR Rubric）

每个开发任务必须满足 TAR 原则。

## TAR 三维度

| 原则 | 说明 | 必需内容 |
|------|------|----------|
| **可测试 (Testable)** | 可通过自动化或手动测试验证 | 测试方法和预期结果 |
| **可验收 (Acceptable)** | 有明确的验收标准 | 具体、可量化的完成标准 |
| **可审查 (Reviewable)** | 可独立进行代码审查 | Review 要点 |

## 具体性检查

| 检查项 | 合格标准 | 不合格示例 |
|--------|---------|-----------|
| 文件路径 | 明确到文件名 | "修改相关文件" |
| 方法/接口 | 明确到方法名或接口名 | "调整接口" |
| 测试方法 | 指定测试类型和编号 | "编写测试" |
| 任务粒度 | 预估 ≤ 4h | 超过 4h 应拆分 |
| 依赖关系 | 明确前置任务编号 | "依赖其他任务" |

## 自检清单

每个功能点的任务设计完成后对比检查：

- [ ] TAR 三字段是否与首批一致（无缺项）
- [ ] 文件路径是否具体到文件名（非"相关文件"等模糊描述）
- [ ] 依赖关系无环
