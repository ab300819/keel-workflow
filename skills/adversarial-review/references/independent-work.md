# 独立出方案 / 独立调研

第三方不审已有产物，而是**从同一个问题出发独立给出答案**，再与我方对照。审查模式找的是「这份东西哪里错」，本模式找的是「换一个人从零做，会不会得出不同结论」——后者能暴露审查发现不了的问题：方向本身选错、漏掉了整类方案。

| 任务 | 第三方产出 | 典型触发 |
|---|---|---|
| 独立出方案 | 方案 + 关键取舍 + 放弃的备选 | 「让 codex 也出一版」「独立给个方案对比下」 |
| 独立调研 | 结论 + 证据 + 未查证项 | 「让第三方查一下 X 是否可行 / 哪个库合适」 |

## 反锚定：brief 只给问题，不给答案

⛔ **不得把我方方案、设计稿、倾向或已排除项放进 brief。** 第三方一旦看到我方答案，产出就退化成对它的审查，独立性归零。我方已有方案时，先封存，等第三方输出后再拿出来对照。

brief 必须包含：

- **用户原话**：逐字引用，⛔ 不得用我方复述替代（复述已带我方理解）
- **硬约束**：用户明确给出的范围、技术栈、不可改动项
- **可读范围**：仓库路径、相关文件；调研需要联网时说明

```markdown
## 独立任务

**任务类型**：独立出方案 / 独立调研
**用户原话**：
> <逐字引用>

**硬约束**：<用户明确的约束；没有写"无">
**可读范围**：<路径 / 是否允许联网>

**输出要求**：
1. 结论或方案（方案须写关键取舍和放弃的备选及原因）
2. 关键假设：哪些前提不成立时结论会变
3. 证据：每条事实断言附来源（文件:行号 / 命令输出 / URL），没有来源的标「推断」
4. 把握程度：高 / 中 / 低，附一句依据
5. 未查证项：想查但没查到或无权查的

## 输出收尾（强制）

⛔ 无论结论如何，你的输出**必须**以下面这一行结束，前后不加任何字符：

=== END OF REVIEW ===
```

尾标记与审查模式同一个，截断判定直接复用 [external-reviewer-integration.md § 方案/设计/文档审查](external-reviewer-integration.md)。

## 调度

复用 SKILL.md S3 的全部通道、失败分类、截断与额度停下规则，走 T1 的 stdin 文本路径（无 schema）。差异只有两处：

- **联网**：调研需要联网时加 `--search`，⛔ 它是顶层参数，须写在 `exec` 之前：`codex --search exec --sandbox read-only ...`（写在 `exec` 之后会被拒绝）
- **T3 折损更重**：同模型独立出方案，基本会得出与我方相同的方向。降到 T3 时除标 `degraded_detection: true` 外，结论里写明「本轮无独立性，仅供参考」

## 消费

1. **原样展示**：同 S4，先完整展示第三方输出，不做改动或过滤
2. **核实事实断言**：抽查第三方给出来源的断言（文件是否存在、API 是否如其所述、URL 是否支持该结论）；核实不了的标出来，⛔ 不得默认它成立
3. **对照**（我方有方案时）：只列分歧，⛔ 不逐条复述两边一致的部分

   | 议题 | 第三方 | 我方 | 核实结论（附证据） |
   |---|---|---|---|

   分歧的核实与审查驳回同一标准：判谁对必须引用代码/文档，不能只说「我方更好」。
4. **用户决策**：用 AskUserQuestion 让用户选采纳第三方 / 保留我方 / 按分歧逐项取舍，每个选项写明不选它的后果

健康分、收敛检测和熔断不适用（没有发现列表）。默认一轮；追问由用户决定，每次追问带上上轮输出重新调用。

## 摘要

yaml-summary-v1 照常输出：`review_type` 填「独立方案」或「独立调研」，`headline` 写第三方结论与分歧数，findings 相关计数填 0。
