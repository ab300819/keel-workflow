# 追溯健康度检查 (--audit)

> 检测编号体系的完整性，防止"Sync Debt（文档维护债）"积累。

## 检查项目

| 检查项 | 检查内容 | 健康标准 |
|--------|----------|----------|
| **AC 覆盖** | 每个 AC-XXX 是否被测试覆盖 | 100% AC 有关联测试 |
| **F 任务闭环** | 每个 F-XXX 是否有任务，任务是否完成 | 所有 F 有任务且闭环 |
| **INS 转化** | 已确认的 INS-XXX 是否转化为 F | 确认的 INS 已转化 |
| **孤立编号** | 是否存在无关联的测试/任务 | 无孤立编号 |
| **needs review 报龄** | 未闭合待定项的归属、关闭条件与年龄 | 无缺字段项、无超龄项 |

| 编号 | 类型 | 问题 |
|------|------|------|
| UT-015 | 单元测试 | ⚠️ 未关联任何 AC |
| T-12 | 任务 | ⚠️ 未关联任何 F |

## needs review 未闭合项报龄

`01-requirements.md` 的 `needs review` 块条目（字段规则见 [requirements](../../requirements/SKILL.md)）逐条判：

| 条件 | 级别 |
|---|---|
| 缺 `归属` 或 `关闭条件` | ⚠️ **立即** —— 没人负责的待定项等于永久待定 |
| 缺 `提出` 日期 | ⚠️ 无法报龄，要求补 |
| `提出` 距今 ≥60 天 | ⚠️ 附具体天数 |
| `提出` 距今 ≥120 天 | ⚠️ 附天数 + 建议本轮关闭 |

天数算法：`提出` 为 ISO 日期，与当前日期作差。⛔ **不用「躺过几个版本」**——「已发布版本」无权威源（git tag / 商店版本 / release note / 里程碑各不相同），算出来不可复核。

> ⚠️ 60 / 120 天是**默认值，非实测**。项目 `AGENTS.md` 可写 `devdocs.needs_review_aging: {warn: N, block: M}` 覆盖。

## 修复建议

1. **AC-003 缺失测试**
   - 建议：补充 UT 或 IT 测试用例
   - 运行：`/ms-test-cases` 补充

2. **F-003 无任务**
   - 建议：拆分开发任务
   - 运行：`/ms-dev-tasks`

3. **孤立编号 UT-015**
   - 建议：指定关联的 AC 编号
   - 或：确认是否为无效测试
```

## 使用场景

# 完整同步时自动包含健康度摘要
/ms-sync
# → 在进度报告末尾显示健康度评分
```
