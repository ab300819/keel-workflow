# 文档归档功能

随着项目迭代，文档会不断膨胀。归档功能帮助控制文档规模，同时保留历史记录便于追溯。

## 归档命令

```bash
/sync --archive              # 全量归档检查（检测所有文档）
/sync --archive requirements # 仅归档需求文档
/sync --archive design       # 仅归档设计文档
/sync --archive tests        # 仅归档测试用例
/sync --archive tasks        # 仅归档开发任务
```

## 归档触发条件

同步时自动检测以下条件，满足任一即建议归档：

| 文档类型 | 行数阈值 | 数量阈值 | 状态条件 |
|---------|---------|---------|---------|
| 需求 (`01-requirements.md`) | > 400 行 | 功能点 > 20 个 | 状态为"已完成"或"已废弃" |
| 设计 (`02-system-design.md`) | > 500 行 | - | 关联功能已归档 |
| 测试 (`03-test-cases.md`) | > 400 行 | 测试用例 > 50 个 | 关联 AC 已归档 |
| 任务 (`04-dev-tasks.md`) | > 300 行 | 已完成 > 15 个 | 状态为"已完成" |

满足条件时，在偏差报告中提示：

```
⚠️ 建议归档：
  - 需求文档：已完成功能 8 个，可归档
  - 任务文档：已完成任务 18 个，超过阈值 15 个
是否执行归档？[全部/选择/跳过]
```

## 各文档归档规则

### 1. 需求文档归档

**归档条件**：功能点状态为"已完成"或"已废弃"

⛔ **归属里程碑尚未通过人工验证的 F 不归档**（`01-requirements.md` §2.5 该 M 的「验收状态」非 `✅ 已验证`）。
F 的"实现完成"由 `/sync` 维护，**它不等于该里程碑已通过人工验证**——两者是不同的事实。
此时归档会把 §2 的归属列连同 F 行一起移走，而那是 `F → M` 的唯一权威源：段末停点将拿不到成员，验收证据先于验收消失。
里程碑验收通过后按常规归档，此后该 M 的成员随 F 淡出属正常（M 的用途是执行期分段，历史 M 不需要能列出成员）。
⛔ 归属列为 `—`（未划里程碑）的 F **不受此条约束**，按原规则归档。

**主文档保留**：
- 所有"待开发"、"开发中"状态的功能点
- 最近完成的 **3 个功能点**（保持上下文）
- 归属里程碑未通过人工验证的功能点（无论状态）
- 背景与目标、非功能性需求等全局信息

**归档内容**：
- 功能点定义（F-XXX）
- 关联的用户故事（US-XXX）
- 关联的验收标准（AC-XXX）
- 追溯矩阵中的对应行

**归档结构**：

```markdown
# 已归档需求

> 最后更新：2024-01-25

## F-001: 用户注册 ✅

**状态**：已完成 | **完成时间**：2024-01-15

### 用户故事

| 编号 | 角色 | 期望 | 目的 |
|------|------|------|------|
| US-001 | 作为新用户 | 我希望使用邮箱注册账号 | 以便获得系统访问权限 |
| US-002 | 作为新用户 | 我希望设置安全密码 | 以便保护我的账号安全 |

### 验收标准

| 编号 | 标准描述 | 状态 |
|------|----------|------|
| AC-001 | 有效邮箱格式可以提交注册 | ✅ |
| AC-002 | 无效邮箱格式显示错误提示 | ✅ |
| AC-003 | 已存在邮箱显示错误提示 | ✅ |

---

## F-002: 用户登录 ✅
...
```

### 2. 设计文档归档

**归档条件**：
- 关联的功能点已归档
- 有新版本设计替代（如 API v1 → v2）
- 设计方案被废弃

**主文档保留**：
- 当前架构概览
- 活跃模块的设计
- 当前使用的 API 和数据模型

**归档内容**：
- 已完成功能的详细设计
- 历史版本 API 设计
- 被废弃的设计方案

**归档结构**：

```markdown
# 已归档设计

> 最后更新：2024-01-25

## F-001: 用户注册 - 设计归档

**归档原因**：功能已完成并稳定运行

### 模块设计

| 模块 | 职责 | 状态 |
|------|------|------|
| UserModule | 用户注册、信息管理 | 已完成 |

### 接口设计

#### IUserService.createUser

| 参数 | 类型 | 说明 |
|------|------|------|
| dto | CreateUserDTO | 创建用户数据 |
| **返回** | User | 创建的用户对象 |

### API 设计

- **POST** `/api/v1/users` - 创建用户

---

## 历史版本

### API v1 (已废弃)

**废弃原因**：迁移至 v2，增加了字段验证
**废弃时间**：2024-01-20

...
```

### 3. 测试用例归档

**归档条件**：
- 关联的 AC 已归档
- 测试已废弃（功能移除）
- 测试重构后旧用例不再需要

**主文档保留**：
- 所有活跃的测试用例
- 追溯矩阵（仅活跃部分）

**归档内容**：
- 已归档 AC 对应的测试用例
- 废弃的测试用例
- 历史版本的测试

**归档结构**：

```markdown
# 已归档测试用例

> 最后更新：2024-01-25

## F-001: 用户注册 - 测试归档

### 单元测试

| 编号 | 测试描述 | 验证 AC | 最终状态 |
|------|----------|---------|---------|
| UT-001 | 验证邮箱格式校验 | AC-001, AC-002 | ✅ 通过 |
| UT-002 | 验证密码强度校验 | AC-004, AC-005 | ✅ 通过 |

### 集成测试

| 编号 | 测试描述 | 验证 AC | 最终状态 |
|------|----------|---------|---------|
| IT-001 | 完整注册流程 | AC-001~005 | ✅ 通过 |

---

## 废弃测试

### UT-OLD-001: 旧版邮箱验证

**废弃原因**：重构为 UT-001
**废弃时间**：2024-01-10
```

### 4. 开发任务归档

**归档条件**：
- 任务状态为"已完成"
- 已完成任务超过 15 个
- 主文档超过 300 行

**主文档保留**：
- 所有"待开发"和"进行中"任务
- 最近完成的 **5 个任务**
- 执行检查清单

**归档结构**：

```markdown
# 已归档任务

> 最后更新：2024-01-25

## F-001: 用户注册

- **测试结果**：UT-001~003, IT-002 通过
```

## 归档流程

```
1. 检测归档条件
   │
   ├── 未满足 → 正常同步
   │
   └── 满足 → 显示归档建议
         │
         ├── 用户跳过 → 正常同步
         │
         └── 用户确认
               │
               ▼
2. 识别待归档内容
   ├── 需求：已完成/已废弃的 F-XXX 及关联 US/AC
   ├── 设计：关联 F 已归档的设计内容
   ├── 测试：关联 AC 已归档的测试用例
   └── 任务：已完成且不在"最近N个"内
         │
         ▼
3. 级联归档检查
   └── 归档 F-001 时，询问是否同时归档关联的设计/测试/任务
         │
         ▼
4. 更新归档文件
   ├── 按功能点分组追加
   ├── 记录归档时间
   └── 更新归档索引
         │
         ▼
5. 更新主文档
   ├── 移除已归档内容
   ├── 保留最近完成项
   └── 添加归档引用链接
```

## 归档后的主文档

归档后，主文档顶部添加归档引用：

```markdown
# 需求文档：项目名称

> 📦 已归档内容请查看 [archive/01-requirements-archive.md](archive/01-requirements-archive.md)
>
> 归档索引：[archive/index.md](archive/index.md)

## 1. 背景与目标
...
```

## 归档约束

- [ ] **归档前必须确认**：显示待归档内容摘要，用户确认后执行
- [ ] **保留追溯链**：归档内容保留完整的编号关联（F→US→AC→Test→Task）
- [ ] **级联提示**：归档需求时提示关联的设计/测试/任务是否一并归档
- [ ] **索引同步**：每次归档后更新 `archive/index.md`
- [ ] **时间记录**：归档内容标注归档时间，便于追溯

## 从归档恢复

如需将归档内容恢复到主文档（如重新开发已废弃功能）：

```bash
# 手动操作，暂不支持命令
1. 从归档文件复制对应内容
2. 粘贴到主文档适当位置
3. 更新状态为"待开发"
4. 从归档文件和索引中移除
```

## 版本归档（可选）

对于里程碑版本，可创建完整快照：

```
docs/devdocs/archive/
└── releases/
    ├── v1.0.0/                 # 版本快照
    │   ├── 01-requirements.md
    │   ├── 02-system-design.md
    │   ├── 03-test-cases.md
    │   └── 04-dev-tasks.md
    └── v2.0.0/
        └── ...
```

触发命令：

```bash
/sync --archive --release v1.0.0
# 创建当前所有文档的版本快照
```
