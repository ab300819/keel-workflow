# L 组 LLM 排版毛病参考

> 配合 [SKILL.md](../SKILL.md) 使用。本文件是 L 组（LLM 输出排版毛病）的知识底座，覆盖 L1–L3 三条规则的可量化判据、语意承载豁免表，并记录被删除的三项越界规则——它们曾在原方案中出现，因涉及删改内容而不实现，须完整保留在此处，防止将来被误当作遗漏而重新引入。
>
> 本组与 M / T 两组的区别：M 组出处是 markdownlint，T 组出处是国标与排版指北，**L 组是新增规则，无外部权威源**——判据来自本 skill 对 LLM 输出常见毛病的观察，因此更须靠"判据可量化"来保证 AI 每次判定一致。

## 1. 边界原则

**本组只碰 Markdown 标记与结构，不删内容。**

这是 [markdown-rules.md](markdown-rules.md)、[cjk-typography.md](cjk-typography.md) 共享的同一条边界原则在 L 组的落地。L 组三条规则全部为 `report`（只报告），无自动修复、无可直接应用的改写建议——原方案曾将 L1/L2 定为"可应用的改写建议"，审查指出删 emoji 或去加粗仍可能删减语意，已改为只报告。

**两个自欺点**（判定 L 组检出时最容易复发，须逐条对照）：

1. **"只改 Markdown 标记"不等于"不改语意"**——标记、强调、emoji、结构本身都可能承载语意。删掉 `🔒 仅管理员可见` 的 emoji 会丢信息；把独占一行的加粗改成标题会改变目录与锚点；删掉 `**必须**` 的加粗会削弱规范强度。
2. **"需要人确认的 assist"不等于"在边界内"**——生成一个可直接应用的语意改写 diff，仍是在做语意改写，不因为最终由人点确认而回到边界内。

## 2. 三条规则

全部为**只报告**，无自动修复、无改写建议。

| ID | 规则 | 判据 |
|---|---|---|
| L1 | emoji 装饰滥用 | 标题行含**装饰性** emoji；或同级列表中 ≥ 3 项以装饰性 emoji 开头 |
| L2 | 加粗滥用 | 单段内 ≥ 3 组完整加粗标记；或整段/整句被加粗包裹；或独占一行的加粗文本后紧跟正文（与 MD036 重叠时以 MD036 为准） |
| L3 | 结构滥用 | 列表嵌套 > 3 层；或列表仅含 1 项 |

判据均可量化（计数、层级、是否独占一行），不依赖"看起来是否装饰过度"这类主观判断——这是三条规则区别于人工文风审查的地方，也是本组仍能保持"事后审查一致性"的前提。

### 2.1 L1 emoji 装饰滥用

**判据**：

- 标题行（ATX `#`–`######` 或 Setext）含**装饰性** emoji；
- 或同级列表（同一父节点下的兄弟项）中 ≥ 3 项以**装饰性** emoji 开头。

低于 3 项的同级列表即使有 emoji 开头，不计入检出——单个或两个 emoji 标记更可能是有意的视觉分组，量少时误报成本高于漏检成本。

**两条判据都只针对装饰性 emoji。** §3 豁免表列出的承载语意用法**不限出现位置一律豁免**，标题行同样豁免：`## 🟢 正常状态`、`## ⛔ 错误级别` 不是 L1 检出对象，而 `## 🎉 快速开始`、`## 🚀 部署上线` 是。区别不在位置也不在数量，而在**删除后是否有事实丢失**。

这条曾是歧义点：L1 判据原写作「标题行含 emoji」，豁免表又不说豁免是否适用于标题位置，于是 `## 🟢 正常` 该不该报无法确定。现裁决为豁免不限位置，两处表述已对齐（对照样例见 [fixtures.md](fixtures.md) L-01 / L-02）。

### 2.2 L2 加粗滥用

**判据**（三选一命中即检出）：

- 单段内出现 ≥ 3 **组完整加粗标记**（即 ≥ 6 个 `**`）；
- 整段或整句被加粗包裹（`**` 包住的范围覆盖了一整个句子或一整段，而非局部词语）；
- 独占一行的加粗文本后紧跟正文——与 `MD036`（用强调冒充标题）判据重叠，**重叠时以 MD036 结论为准**，L2 不重复报告，避免同一处产生两条不同规则的检出。

**「段」与阈值的两处收敛**，均来自首次真实运行的实测误报（对照样例见 [fixtures.md](fixtures.md) L-03 / L-04）：

- **阈值从「≥ 3 处 `**`」改为「≥ 3 组完整加粗标记」。** 原写法按标记符个数计，两组并列加粗（4 个 `**`）即命中。实测 `docs/workflows.md` 正文有 2 段命中，全部是 `A**甲**或**乙**` 式的并列强调——正常技术写作，非滥用；本仓 `AGENTS.md`、`README.md` 同类写法普遍存在。三组是「滥用」的合理起点，两组不是
- **「段」指 CommonMark 段落，列表的每一项各自成段。** 不把整个列表按一段合并计数：`- **期望**：…` / `- **理由**：…` 两项合起来就有 4 个 `**`，若按一段计，本仓几乎所有文档都会命中 L2。逐项计数各为 1 组，均不到线

检出须附提示（见 §1 边界原则第 1 点的具体化）：

- `**必须**` 这类加粗承载规范强度，删除会削弱语义，不应无条件建议去除；
- 独占一行的加粗若改为标题，会改变目录、锚点与层级——这不是排版层面的等价变换，须提示用户自行判断是否要提升为标题结构。

### 2.3 L3 结构滥用

**判据**：

- 列表嵌套超过 3 层（第 4 层及以上）；
- 或列表仅含 1 项（用列表包裹单条内容，未形成真正的并列关系）。

## 3. 语意承载豁免表（不计入 L1，不限位置）

以下 emoji 用法不触发 L1 检出，因为删除会丢失它们承载的信息，不属于"装饰性"用法。**豁免不限出现位置**——标题行、列表项、正文、表格单元格一律适用（见 §2.1 末段的裁决）：

| 豁免类型 | 示例 | 说明 |
|---|---|---|
| 表格单元格内的 emoji | `\| 状态 \| 🟢 正常 \|` | 表格已是结构化容器，单元格内的 emoji 是内容的一部分而非标题/列表的装饰前缀 |
| 级别标记紧邻说明文字 | `⛔ 错误`、`⚠️ 警告`、`ℹ️ 提示`、`✅ 通过` | 四个符号在本 skill 自身的分级体系中就是级别的组成部分，紧邻文字说明时是标记不是装饰 |
| 承载信息的状态标记 | 🟢 🟡 🔴 | 删除即丢失"正常/警告/异常"这类状态信息，等价于删内容 |
| 承载信息的权限标记 | 🔒 | 删除即丢失"受限/需要权限"这一信息，同上 |

豁免表的共同特征：这些 emoji 不是可有可无的视觉点缀，去掉后读者会丢失一条明确的事实（状态、级别、权限），而非仅仅少了一点视觉吸引力。判断某处 emoji 是否落入豁免表，看**删除后是否有信息丢失**，而非"是否好看"。

## 4. 被删除的三项越界规则

原方案曾在 L 组包含以下三项，均因涉及删改内容、越过 §1 边界原则而**已删除**，不实现：

- **结尾套话**（如"希望以上内容对您有帮助"一类收尾语）——判定"是否为套话"需要理解句子意图，删除套话就是删除内容，不是排版整理；**已删除**。
- **无信息量总结**（如复述标题、不提供新信息的总结段）——判定"是否有信息量"需要对比总结与正文的语意重叠度，处理方式必然是重写或删除该段，属语意操作；**已删除**。
- **表格滥用改写**（如把不适合表格的内容硬套成表格，建议改写为段落）——"是否适合表格"是内容组织方式的判断，改写涉及重新表达原文，不是标记调整；**不实现**。

这三项都曾以"越界模式"的名义试图保留（即明确标注为可选、需人工确认的检出项），但审查指出：明示越界只是把风险摆在台面上，不等于消除风险。§1 的边界原则**无例外**，因此三项直接删除，不作为降级或可选项保留。

## 5. 与 M / T 两组的关系

L 组与 MD036（用强调冒充标题）、MD026（标题末尾多余标点）等 M 组规则可能同时命中同一处文本。处理原则：**M 组规则优先**，L 组不对已被 M 组规则覆盖的判据重复报告（见 §2.2 关于 L2 与 MD036 的重叠说明）。这样报告里同一处问题只出现一次，避免使用者困惑"这两条规则谁说了算"。
