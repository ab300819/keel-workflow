# Code Review 详细清单与输出格式

> 配合 [SKILL.md](../SKILL.md) 使用。阈值与黑名单以 [核心阈值表](../SKILL.md#核心阈值表)、[命名规范](../SKILL.md#命名规范)、[注释规范](../SKILL.md#注释规范)、[设计原则（代码级）](../SKILL.md#设计原则代码级) 为权威；反馈分级表见主文件。

## Review 前置检查

- [ ] CI 通过（测试、lint、build）
- [ ] 改动范围合理（单一主题）

## 详细审查维度

### M - 可维护性

- [ ] 核心阈值表合规（函数长度/参数数量/嵌套深度/重复代码/单类行数）
- [ ] 命名合规（分类规则 + 黑名单，见主文件命名规范）
- [ ] 注释合规（白/黑名单，见主文件注释规范）

### T - 可测试性

- [ ] 核心逻辑有测试，依赖可以 Mock
- [ ] 纯函数优先、业务逻辑与 IO 分离

### E - 可扩展性

- [ ] 不为假设需求设计（YAGNI）
- [ ] 只有 1 个实现时不创建接口（例外：跨模块边界 / 外部依赖 / 可测试性边界可先建接口）

### 设计原则（代码级）

- [ ] 六大原则代码级特征无命中（SRP/OCP/LSP/LoD/ISP/DIP，见主文件）

### 错误处理

- [ ] 边界条件处理
- [ ] 不吞掉异常

### 安全检查

- [ ] 无 SQL 注入风险
- [ ] 无 XSS 风险
- [ ] 敏感数据加密/脱敏（不 log 密码、Token）
- [ ] 权限控制正确
- [ ] 错误信息不泄露内部实现细节

## 输出格式

```markdown
## Code Review 报告

### 🚫 Blocker

| # | 文件:行号 | 问题 | 说明 |
|---|----------|------|------|
| 1 | `src/x.ts:45` | 函数过长 (87 行 > 最大值 50) | 拆分为多个职责单一的函数 |

### 💡 Suggestion

| # | 文件:行号 | 问题 | 说明 |
|---|----------|------|------|
| 1 | `src/x.ts:12` | 4 个参数 (> 建议值 3) | 建议使用参数对象 |

### ✅ 良好实践

- 依赖注入使用正确
- 命名清晰准确
```

## 反馈要求

- 区分阻塞和建议，反馈需要说明理由
- 安全问题必须 [Blocker]
- 设计决策不理解时用 [Question]，不直接否定
