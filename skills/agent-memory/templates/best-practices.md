# 记忆文件最佳实践

本文档为 `/agent-memory` skill 的参考规范，同时作为首次创建 AGENTS.md 时的质量基准。

> 核心来源：[agents.md 开放格式规范](https://agents.md)（社区共识）+ Claude Code 官方最佳实践 + 项目实践沉淀。
>
> 本文档在 agents.md 规范的开放框架上，叠加观点性约束（行数限制、质量守则、反模式检测等）。

---

## 核心原则

**每一行都要值得常驻**：写入前自问——"删掉这行，AI 会犯错吗？"如果不会，就删掉。

臃肿的记忆文件会导致 AI 忽略真正重要的规则。

### 质量守则

| # | 守则 | 说明 |
|---|------|------|
| 1 | **短而稳定** | 可删则删，AGENTS.md 不超过 60 行 |
| 2 | **广泛适用** | 仅保留跨任务高频规则，不写单次使用的信息 |
| 3 | **可执行** | 优先命令、约束、检查点，而非长篇解释 |
| 4 | **避免重复** | 领域流程放到 Skill，不塞进记忆文件 |
| 5 | **详情留原地** | 具体实现细节、逐文件说明禁止写入常驻记忆 |
| 6 | **工具无关** | 不包含特定 AI 工具的专属语法或指令 |

## 内容筛选标准

> agents.md 规范建议："anything you'd tell a new teammate"。以下标准在此基础上进一步细化筛选粒度。

### 应写入记忆文件

| 类别 | 示例 |
|------|------|
| AI 无法猜到的命令 | `pnpm test:unit --reporter=dot` |
| 与默认不同的代码风格 | ES modules 而非 CommonJS |
| 测试指令和首选测试框架 | Vitest + Testing Library |
| 仓库约定（分支命名、PR 规范） | `feat/T-XX-描述` |
| 项目特有的架构决策 | ADR-001: 选用 SQLite 而非 PostgreSQL |
| 开发环境特殊要求 | 必需的环境变量、特殊端口 |
| 常见陷阱和非显而易见的行为 | `npm run build` 会清空 dist/ |

### 不应写入记忆文件

| 类别 | 理由 |
|------|------|
| AI 通过读代码能推断的信息 | 增加噪音，无额外价值 |
| 标准语言惯例 | AI 已经知道 |
| 详细 API 文档 | 应链接到文档，不内联 |
| 频繁变动的信息 | 维护成本高，容易过时 |
| 长篇解释或教程 | 违反"短而稳定"原则 |
| 逐文件的代码库描述 | 太详细，应留在原地 |
| 不言自明的要求 | 如"写干净的代码" |

## AGENTS.md 结构规范

### 可选章节

按项目所需选用，已有清晰结构不必重排。文档链接注明何时需要读；单次小改动不要求遍历整个资料目录。

```markdown
# <项目名称>

## 技术栈        ← 3-5 行，框架 + 语言 + 关键依赖
## 架构决策      ← ADR 编号 + 一句话摘要
## 领域术语      ← 术语表，防止误解
## 当前状态      ← 权威任务台账链接；必要时附可维护的摘要
## 命令          ← 运行/测试/构建命令
## 约定          ← 已有提交格式与验证要求，不默认添加指标
## 详细文档      ← 指向 docs/ 的链接（不内联）
```

### 行数限制

- AGENTS.md **不超过 60 行**
- 超过时优先删减"架构决策"和"领域术语"中的次要条目
- 详细内容留在 `docs/` 目录，记忆文件仅保留摘要和链接

### 多位置策略（CLAUDE.md 专属）

CLAUDE.md 可放置在多个位置，实现分层覆盖：

| 位置 | 作用域 | 典型用途 |
|------|--------|----------|
| `~/.claude/CLAUDE.md` | 所有项目 | 个人偏好、通用规则 |
| 项目根目录 `./CLAUDE.md` | 当前项目 | 团队共享的项目规则 |
| 父目录 | Monorepo 根 | 跨子项目的通用规则 |
| 子目录 | 按需加载 | 子模块特有的规则 |

> 本项目中 CLAUDE.md 通过 `@AGENTS.md` 导入，无需维护镜像副本。多位置策略仅供参考。

## 反模式

### 来自官方最佳实践

| 反模式 | 症状 | 修复 |
|--------|------|------|
| **过度指定** | 记忆文件太长，AI 忽略一半规则 | 无情裁剪；AI 已正确执行的规则直接删除 |
| **规则被忽视** | AI 反复违反某条规则 | 文件可能太长导致规则被淹没，或措辞有歧义 |

### 记忆文件特有反模式

| 反模式 | 症状 | 修复 |
|--------|------|------|
| **信息搬运工** | 把文档内容复制到 AGENTS.md | 只写摘要 + 链接，详情留原地 |
| **工具绑定** | 写入 `<!-- cursor:ignore -->` 等工具专属语法 | AGENTS.md 保持工具无关 |
| **快照陷阱** | "当前状态"长期不更新，误导 AI | 优先链接任务台账；确需摘要时随来源更新 |
| **术语堆砌** | 领域术语表超过 10 条 | 仅保留高频 + 易混淆的术语 |
| **命令罗列** | 列出所有可用命令 | 仅保留 AI 无法从配置文件推断的命令 |

## 诊断与维护

### 规则被忽视时的排查

1. **文件是否太长？** → 裁剪到 60 行以内
2. **措辞是否有歧义？** → 改为明确的约束或命令
3. **范围是否正确？** → 写清触发条件、已有授权和完成条件；不要用加强语气替代诊断
4. **是否需要机械保障？** → 可确定判定且反复失败的规则考虑脚本或 Hook；先核对环境能力

### 定期维护

- 像对待代码一样对待记忆文件：出问题时审查、定期裁剪、观察行为变化
- 将 AGENTS.md 纳入版本控制，团队可贡献
- 记忆文件的价值随时间复利增长

## 与 `/init` 的配合

| 阶段 | 负责方 | 说明 |
|------|--------|------|
| 首次创建 | `/agent-memory` | 从项目源扫描创建；若 `/init` 已创建则增量更新 |
| 质量基准 | 本文档 | 创建和更新时参考此文档的筛选标准 |
| 后续更新 | `/agent-memory --update` | 从项目源提取信息，同步 AGENTS.md |
| 结构重组 | `/agent-memory --restructure` | 按本文档规范重组记忆文件 |

> `/init` 的产出因工具而异。`/agent-memory` 不依赖 `/init` 创建 AGENTS.md，可独立完成首次创建。
