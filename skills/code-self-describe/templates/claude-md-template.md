# 模块级 CLAUDE.md 模板

## 标准模板

```markdown
# <模块名>

## 地位

<在系统中的角色和位置，1-2 句话>

## 逻辑

<模块做什么，核心功能描述，3-5 句话>

## 约束

- <使用规则 1>
- <使用规则 2>
- <依赖限制>

## 业务域清单

| 文件/子模块 | 职责 |
|-------------|------|
| `xxx.ts` | <职责描述> |
| `yyy/` | <子模块描述> |
```

## 完整示例

### 用户模块

```markdown
# 用户模块 (user)

## 地位

系统核心业务模块，负责用户生命周期管理，是认证模块和订单模块的上游依赖。

## 逻辑

处理用户注册、登录凭证管理、个人信息维护和账户状态控制。
通过 UserRepository 持久化数据，通过 ValidatorService 校验输入。
对外暴露 UserService 作为唯一入口，禁止直接访问 Repository。

## 约束

- 外部模块只能通过 UserService 访问，不可直接引用 Repository
- 用户敏感信息（密码、手机号）必须脱敏后才能返回
- 删除操作使用软删除，不物理删除数据

## 业务域清单

| 文件/子模块 | 职责 |
|-------------|------|
| `user.service.ts` | 用户业务逻辑入口（CRUD、状态管理） |
| `user.repository.ts` | 用户数据持久化（数据库操作） |
| `user.dto.ts` | 请求/响应数据传输对象定义 |
| `user.entity.ts` | 用户实体定义（数据库映射） |
| `user.validator.ts` | 用户输入校验规则 |
| `user.types.ts` | 用户相关类型定义 |
```

### 认证模块

```markdown
# 认证模块 (auth)

## 地位

系统安全网关，负责身份验证和访问控制，依赖用户模块获取用户信息。

## 逻辑

处理登录认证（JWT 签发/验证）、会话管理和权限控制。
AuthGuard 作为中间件拦截请求，验证 Token 有效性。
RoleGuard 基于用户角色控制接口访问权限。

## 约束

- Token 密钥必须从环境变量读取，禁止硬编码
- 认证失败统一返回 401，权限不足统一返回 403
- 刷新 Token 有效期不超过 7 天

## 业务域清单

| 文件/子模块 | 职责 |
|-------------|------|
| `auth.service.ts` | 认证业务逻辑（登录、Token 管理） |
| `auth.guard.ts` | 请求认证中间件 |
| `auth.controller.ts` | 认证相关 API 端点 |
| `role.guard.ts` | 角色权限控制中间件 |
| `strategies/` | Passport 认证策略（JWT、Local） |
```

## 自动生成标记

自动生成的 CLAUDE.md 内容使用标记区分，便于 --update 模式识别可安全更新的部分：

```markdown
<!-- auto-generated by /code-self-describe -->
## 业务域清单

| 文件/子模块 | 职责 |
|-------------|------|
| `user.service.ts` | 用户业务逻辑入口 |
<!-- end auto-generated -->
```

手动编写的部分不带标记，--update 模式不会修改。
