# 层级更新传播规则

## 核心原则

```
代码变更 → 文件头部注释 → 所在目录 CLAUDE.md → 上级目录 CLAUDE.md → ... → 项目根 CLAUDE.md
```

**只在公共接口变化时向上传播**，内部重构不触发。

## 变更类型与传播范围

| 变更类型 | 更新头部注释 | 更新所在模块 CLAUDE.md | 向上传播 |
|---------|------------|---------------------|---------|
| 新增 export 函数/类 | ✅ OUTPUT 变化 | ✅ 业务域清单更新 | ✅ |
| 新增 import 依赖 | ✅ INPUT 变化 | ❌ 模块职责未变 | ❌ |
| 删除 export 函数/类 | ✅ OUTPUT 变化 | ✅ 业务域清单更新 | ✅ |
| 重命名函数（不改签名） | ✅ OUTPUT 名称变化 | ✅ 业务域清单更新 | ❌ |
| 内部实现重构 | ❌ 接口未变 | ❌ | ❌ |
| 新增文件 | ✅ 生成新注释 | ✅ 业务域清单新增 | 视文件角色 |
| 删除文件 | — | ✅ 业务域清单移除 | 视文件角色 |
| 新增子目录/模块 | — | ✅ 业务域清单新增 | ✅ |

## 自动/手动内容区分

### 标记规则

自动生成的内容使用 HTML 注释标记：

```markdown
<!-- auto-generated by /code-self-describe -->
## 业务域清单

| 文件/子模块 | 职责 |
|-------------|------|
| `user.service.ts` | 用户业务逻辑入口 |
| `user.repository.ts` | 用户数据持久化 |
<!-- end auto-generated -->

## 约束

（手动编写的内容，不带标记，--update 不会修改）
- 外部模块只能通过 UserService 访问
```

### 更新规则

| 内容区域 | 标记 | --update 行为 |
|---------|------|-------------|
| 自动生成区域 | `<!-- auto-generated -->` | 安全覆盖 |
| 手动编写区域 | 无标记 | **不修改** |
| 混合区域 | 部分标记 | 只更新标记内的部分 |

## Update 模式详细流程

### Step 1: 确定变更范围

```bash
# 获取自上次提交以来的变更文件
git diff --name-only HEAD

# 或获取自上次描述更新以来的变更
git diff --name-only <last-describe-commit>
```

过滤规则：
- 排除非源码文件（.md, .json, .yaml 等配置文件）
- 排除测试文件（仅更新头部注释，不影响模块 CLAUDE.md）
- 排除隐藏文件和构建产物

### Step 2: 分析每个变更文件

```
对每个变更文件:
  1. 读取当前文件内容
  2. 分析 import 语句 → 新 INPUT
  3. 分析 export 声明 → 新 OUTPUT
  4. 对比现有头部注释
  5. 如有差异 → 更新头部注释
```

### Step 3: 聚合模块级变更

```
对每个受影响的模块:
  1. 收集该模块下所有变更文件的信息
  2. 读取现有 CLAUDE.md
  3. 更新自动生成区域（业务域清单）
  4. 如模块职责发生显著变化 → 提示用户确认逻辑描述更新
```

### Step 4: 向上传播

```
从变更模块开始，逐级向上:
  1. 检查父模块的 CLAUDE.md
  2. 如子模块的 OUTPUT 变化影响父模块描述 → 更新
  3. 重复直到根 CLAUDE.md
  4. 仅更新自动生成区域
```

## 冲突处理

| 场景 | 处理 |
|------|------|
| 自动描述与手动描述矛盾 | 保留手动描述，终端提示冲突 |
| 文件已删除但 CLAUDE.md 仍引用 | 从业务域清单移除，终端提示 |
| 新文件无法推断 POS | 使用目录名推断，标记为待确认 |
| 根 CLAUDE.md 已有自定义结构 | 只追加/更新模块描述章节 |
