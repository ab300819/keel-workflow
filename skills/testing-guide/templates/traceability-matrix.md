# 需求-测试追溯矩阵模板

## 编号规范

| 类型 | 前缀 | 格式 | 说明 |
|------|------|------|------|
| 功能点 | F | F-XXX | 用户可感知的独立功能 |
| 用户故事 | US | US-XXX | 用户使用场景 |
| 验收标准 | AC | AC-XXX | 可量化的完成条件 |
| 单元测试 | UT | UT-XXX | 验证内部逻辑 |
| 集成测试 | IT | IT-XXX | 验证组件协作 |
| E2E 测试 | E2E | E2E-XXX | 验证用户场景 |

## 测试代码里不写编号

⛔ 测试代码不写 `// UT-001: AC-001`、`@testId`、`@acceptance` 这类 keel 编号标注。AC 与测试编号的映射只在本追溯矩阵里维护，代码里不留第二份；测试名用自然语言说明被验证的行为即可。规则见 [testing-guide SKILL.md](../SKILL.md)。

## 维护建议

1. **新增需求时**
   - 在需求文档中分配 F/US/AC 编号
   - 在追溯矩阵中添加条目，状态标记为 ❌

2. **编写测试时**
   - 测试名说明被验证的行为（⛔ 不写 AC 编号标注）
   - 更新追溯矩阵状态

3. **定期审查**
   - 对照追溯矩阵核对每条 AC 是否有通过的测试（`/test-run` 的追溯验证）
   - 确保 P0 验收标准 100% 覆盖

4. **CI 集成**
   - P0 验收标准未覆盖时构建失败
   - 生成追溯覆盖报告
