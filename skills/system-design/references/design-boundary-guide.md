# 设计边界指南（设计 vs 实现）

> 配合 `/system-design` 使用。本文回答一个问题：**一段描述应该写进设计文档、还是属于实现？**

## 核心判据

**设计层**回答 "做什么"（What）和 "为什么"（Why）：
- 模块边界、职责、依赖方向
- 接口签名、行为契约（前置/后置/错误）
- 数据模型语义、实体关系
- 关键决策的选型理由

**实现层**回答 "怎么做"（How）：
- 具体算法、控制流、循环/分支
- 内部数据结构、状态机、临时变量
- 重试/超时/退避等具体策略数值
- 文件/目录/类命名细节

若一段描述去掉后仍能让 Test Agent 基于 §5 行为契约写出测试，那它很可能不属于设计层。

## 越界反例表（7 类）

| 越界类型 | ❌ 反例（实现层） | ✅ 正例（设计层） |
|---------|----------------|-----------------|
| 算法细化 | "先查缓存，命中返回；未命中查 DB 后写回缓存" | 行为契约：`get(id)` 后置 "返回最新状态"；性能契约 "P99 < 50ms" |
| 内部状态 | "维护 `pendingRequests: Map<string, Promise>` 去重" | 行为契约：重复请求合并，返回同一结果 |
| 控制流 | "for each user: if user.active && user.verified..." | 输入 `users[]`；后置 "返回满足 `active ∧ verified` 的子集" |
| 伪代码 | 在代码围栏内写 `function foo() { const x = ...; return ...; }` | 方法签名 `foo(input: Input): Output` + 行为契约表 |
| 字段注释性描述 | "`name` 字段，用 trim() 去空格再存" | 实体 `name: string`；前置 "非空、长度 1~50、已去首尾空格" |
| 时序/重试策略细化 | "超时 3s 后重试 3 次，退避 100ms→200ms→400ms" | 行为契约 "`put` 幂等可重试"；错误契约 `TIMEOUT` 抛给调用方；SLA "最终一致性 ≤5s" |
| 依赖耦合到实现 | "AuthService 依赖 `PostgresUserRepository`" | "AuthService 依赖 `IUserRepository`"（实现由 DI 注入） |

## 设计边界自查清单（L3 接口层完成时强制执行）

在完成 §5 核心接口章节、进入下一层确认前，勾选以下项：

- [ ] 每个接口只描述"做什么"（签名+契约），未描述"怎么做"（步骤/循环/分支）
- [ ] 未引入仅为实现服务的内部数据结构（Map/Queue/State/Cache 等）
- [ ] 未出现伪代码块（代码围栏内写逻辑）
- [ ] 字段定义只说明语义和约束，未描述存储/转换过程
- [ ] 未硬编码具体时序策略（超时/重试/退避数值）——应作为错误契约或 SLA 处理
- [ ] §4 模块"依赖接口引用"列填的是 `I*(§5.x)` 而非实现类名或裸模块名（单模块填"无"）

任一项未勾选 → ⛔ 禁止继续。恢复方式：按反例表改写为行为契约表述，或把越界内容迁移至 `/dev-workflow` 阶段。

## L3 vs L4 判界（决策 3 关联）

| 归属 | 内容 | 判断法则 |
|------|------|---------|
| L3 接口行为层 | 外部调用方可观察的行为 | 签名、参数、返回值、前置/后置/错误契约 |
| L4 数据模型层 | 外部调用方不可见的持久化细节 | 字段类型/长度/索引、实体关系、存储约束 |

判例：
- `email 必须唯一` → **L3**（调用方通过 `ConflictError(EMAIL_DUPLICATE)` 能观察到）
- `email VARCHAR(320) + UNIQUE INDEX` → **L4**（存储层细节）
- `createUser 后置：返回 id 非空` → **L3**
- `User.id 使用 UUID v7` → **L4**（ID 生成策略）
