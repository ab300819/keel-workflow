# UI→API 映射指南

> 本指南供 system-design 在设计 API 时消费 design_context 和设计稿信息。

## 定位

系统架构师**不负责 UI 视觉与交互实现**（委托 ui-orchestrator），但**消费设计稿中的数据需求和操作映射**来驱动 API 设计。

## 数据来源链

system-design 消费的不是 design_context schema 本身（schema 只记录"设计稿在哪"），而是：

1. **AC 描述**（主要来源）：从 01-requirements.md 的 AC 中提取 UI 数据需求
2. **设计稿结构**（补充来源）：通过 design_context.access_method 读取设计稿 DSL/截图，获取页面结构信息

当两者信息不一致时，以 AC 为准（AC 是需求契约，设计稿是视觉参考）。

## UI→API 映射模式

### 页面数据需求 → API 响应结构

| 设计稿/AC 信息 | API 设计决策 |
|---------------|------------|
| 页面展示哪些字段 | 响应 DTO 包含哪些字段 |
| 数据嵌套关系（如订单→商品列表） | 响应嵌套结构或拆分为子接口 |
| 列表分页需求 | 分页参数设计（cursor/offset） |
| 数据聚合展示（如统计看板） | 聚合接口 vs 多次调用 |

### 用户操作 → API 端点

| 设计稿/AC 信息 | API 设计决策 |
|---------------|------------|
| 表单提交 | POST/PUT 端点 + Request Body 结构 |
| 按钮操作（删除、审批、状态变更） | 对应的 CRUD/状态变更端点 |
| 批量操作（全选、批量删除） | 批量接口设计 |
| 搜索/筛选/排序 | Query 参数设计 |

### 交互状态 → 错误码与状态约定

| 设计稿/AC 信息 | API 设计决策 |
|---------------|------------|
| 错误态展示（表单校验、权限不足） | 错误码体系和错误响应结构 |
| Loading 态 | 接口超时策略、长轮询/WebSocket 需求 |
| 空态展示 | 空列表响应约定（空数组 vs 特殊标记） |
| 权限控制（按钮灰显/隐藏） | 权限信息随数据返回 vs 独立权限接口 |

### 实时性需求 → 通信模式

| 设计稿/AC 信息 | API 设计决策 |
|---------------|------------|
| 实时更新（消息、通知、进度条） | WebSocket / SSE / 轮询 |
| 协作编辑 | CRDT / OT + WebSocket |
| 文件上传/预览 | 上传接口（multipart）+ 存储策略 |

## 何时委托 ui-orchestrator

以下内容**不属于** system-design 职责，应委托 ui-orchestrator：

- 具体组件选择（用哪个 DatePicker）
- 布局/间距/颜色等视觉实现
- 动画/过渡效果
- 响应式断点
- 组件状态管理（UI 内部状态）

## 使用流程

1. 读取 `01-requirements.md` 中的 `## 设计资产` 获取 design_context
2. 如果 `design_files.available=true`，按 access_method 读取设计稿（getDsl / batch_get / 截图）
3. 结合 AC 描述和设计稿页面结构，按上述映射模式设计 API
4. 在 API 设计章节标注数据来源（如"基于 D-01:订单列表页的数据需求"）
