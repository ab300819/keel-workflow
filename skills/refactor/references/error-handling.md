# 错误处理

## 测试失败

```
重构后测试失败。

失败的测试:
- UserService.test.ts: validateUser should return false for invalid email

操作选项:
1. 回滚此次重构步骤
2. 查看失败详情并修复

⛔ 不提供「跳过此测试」：重构后必须所有测试通过。

建议：回滚到上一个通过的状态，重新分析重构方案。
```

## 覆盖率不足

```
当前测试覆盖率不满足重构要求。

目标范围: src/services/user.ts
当前覆盖率:
  - 行覆盖: 45% (要求 ≥80%)
  - 分支覆盖: 38% (要求 ≥80%)

操作选项:
1. **补充测试** - 为未覆盖代码编写测试
2. 标记为不可测试 - 进入重写流程

⛔ 不提供「降低要求、按当前覆盖率直接重构」：无测试或覆盖不足时必须先补测试。
```

## 代码不可测试

```
目标代码被评估为"不可测试"。

原因:
- [x] 硬编码数据库连接
- [x] 业务逻辑与 IO 混合
- [ ] 全局状态依赖

建议进入重写流程:
1. 使用 /retrofit 建立项目基线（记录现状、外部硬约束、已知未知）
2. 与用户确认重写的目标行为 —— 目标不能从旧代码推导
3. 走正常 keel 流程生成需求和设计文档
4. 按照可测试的设计重新实现

是否进入重写流程？
```
