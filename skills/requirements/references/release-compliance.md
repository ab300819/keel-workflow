# 发布 / 分发平台合规采集清单

> **按需加载。** 本文件不在 `/ms-requirements` 默认流程里——加载条件见下「触发」。
>
> 产出落 `01-requirements.md` §6 约束表（`CON-XXX`），⛔ 不新开阶段、不新开文件。

## 为什么需要单独一张清单

`F/US/AC` 的结构假设需求由**用户故事**驱动。平台强制约束不是这个形状：它们没有用户、没有故事，但缺一项就发布阻塞——商店类目缺失直接构建失败，无图标直接驳回，未授权第三方商标按平台条款驳回。

它们也不会被使用者主动想起来。典型症状是**上架前一周才发现有一批工作从没进过任何文档**。

## 触发（两级，⛔ 不得自动展开问卷）

| 级别 | 条件 | 行为 |
|---|---|---|
| **加载问卷** | 用户明说「发布 / 上架 / 提审 / 合规 / 平台配置 / 商店」，**或** 01 §6 已有本文任一类别的 `CON` | 展开命中的组 |
| **一行提示** | 仅检测到平台制品文件（下表），用户没提发布 | ℹ️ 输出**一行**：「检测到 `<文件>`，需要过一遍发布合规清单吗？（`/ms-requirements` 时说「上架」即可）」<br>⛔ **不展开任何问题，不追问，不重复提示** |

平台制品信号：

| 文件 / 目录 | 平台 |
|---|---|
| `Info.plist` / `*.xcodeproj` / `*.xcworkspace` | Apple（iOS / macOS / tvOS / visionOS）|
| `AndroidManifest.xml` / `build.gradle*` | Android |
| `manifest.json`（含 `manifest_version`）| Chrome / Edge 扩展 |
| `pubspec.yaml` | Flutter（多端）|
| `package.json` 含 `"build"` + electron 依赖 | Electron 桌面分发 |
| `*.appxmanifest` | Microsoft Store |

> ⛔ **文件存在只是「要不要问」的开关，不是「必须有 CON」的门。**
> 任意 iOS 项目几乎必然有 `Info.plist`——若据此强推六组问卷，「允许填不适用」仍然是仪式。
> **零信号项目从头到尾看不见这套东西；有信号但用户没提发布的项目只看见一行提示。**

## 六组清单

每组独立，按用户实际平台裁剪。**每题必须提供 `⏭️ 不适用` 出口**，且用户答「不适用」或「不清楚」时 ⛔ 不得追问第二遍。

### 组 1：分发平台元数据

| 问题 | 落地形态 | 缺失后果 |
|---|---|---|
| 应用显示名（各语言）与 bundle / package 标识符定了吗？ | `CON`：标识符与显示名固定值，验证方式 = 读配置断言 | 标识符改不了（上架后永久绑定）|
| 商店类目 / 二级类目选了吗？ | `CON`：配置含类目字段 | Apple 缺 `LSApplicationCategoryType` 直接构建失败 |
| 版本号与构建号的递增规则定了吗？ | `CON`：构建号严格单调递增，验证方式 = 脚本比对上次提交 | 重复构建号提审被拒 |
| 启动屏 / 启动画面配置了吗？ | `CON`：存在且尺寸合规 | 部分平台驳回 |
| 隐私清单 / 数据披露文件齐了吗？ | `CON`：清单文件存在且必填项非空 | Apple `PrivacyInfo.xcprivacy`、Chrome 数据用途披露缺失即驳回 |
| 最低系统版本（平台地板）定了吗？ | `CON`：配置值 = 声明值 | 与实际 API 用法不符会运行时崩溃 |

### 组 2：图标与视觉资产

| 问题 | 落地形态 | 缺失后果 |
|---|---|---|
| 全尺寸应用图标齐了吗？ | `CON`：图标集完整，验证方式 = 脚本枚举尺寸 | **无图标直接驳回** |
| 商店截图（各设备尺寸 / 各语言）齐了吗？ | `CON`：截图目录完整性 | 无法提交 |
| 图标是否含不允许的元素？ | `CON` + 人工档 | 平台条款各异（如 Apple 禁图标带圆角 alpha）|

### 组 3：发行区域与本地化

| 问题 | 落地形态 | 缺失后果 |
|---|---|---|
| 首发区域定了吗？ | `CON`，多为**人工档**（后台设置，无本地制品可检）| 区域决定适用哪国法规 |
| 支持哪些语言？各语言的商店文案齐了吗？ | `CON`：本地化资源文件完整性 | 缺失语言会 fallback 到开发语言 |
| **面向用户的字符串是否全部走了本地化机制**？ | `CON`：验证方式 = 脚本扫描硬编码字面量 | 硬编码文案无法本地化，且改文案要发版 |

### 组 4：第三方商标与文案红线

| 问题 | 落地形态 | 缺失后果 |
|---|---|---|
| 应用名、截图、描述里有第三方商标吗？有授权吗？ | `CON`：验证方式 = 脚本 grep 商标词表 | Apple Guideline 5.2.1 类条款驳回 |
| 有暗示与某平台 / 品牌有官方关系的表述吗？ | `CON` + 人工档 | 同上 |
| 有「最好 / 第一 / 唯一」这类无依据宣称吗？ | 人工档 | 部分平台按虚假宣传处理 |

> **商标词表**建议落项目侧文件（如 `Scripts/trademark-denylist.txt`），由 `CON` 的验证方式引用。
> ⛔ 词表内容属项目私有，不进 skill。

### 组 5：隐私与数据披露

| 问题 | 落地形态 | 缺失后果 |
|---|---|---|
| **实际申请的权限与实际用途一致吗？有没有已经不用了的权限？** | `CON`：验证方式 = 脚本枚举配置中的权限声明并与用途表比对 | 申请无用权限被驳回；且**架构改了权限声明没跟着删是高频漂移点** |
| 每条权限的用途说明文案写了吗（各语言）？ | `CON`：脚本断言每个权限键都有对应说明 | Apple 缺 usage description 运行时崩溃 |
| 收集哪些数据、是否关联身份、是否用于追踪，披露了吗？ | `CON`：披露文件必填项 | 与实际行为不符属虚假披露 |
| 有三方 SDK 吗？它们各自收集什么？ | `CON` + 人工档 | 平台要求逐 SDK 披露 |

> 组 5 第一题**必问**（在问卷已加载的前提下）。它是「架构变了但配置留在旧世界」的高发位置——
> 删掉一条读授权链路后，配置里的权限声明与守卫脚本里的必需项检查往往双双留着。

### 组 6：平台备案与资质

| 问题 | 落地形态 | 缺失后果 |
|---|---|---|
| 目标区域要备案 / 许可 / 资质证明吗？ | 人工档 `CON` | 部分区域无备案不得上架 |
| 有年龄分级问卷要填吗？分级依据记录了吗？ | 人工档 `CON` | 分级错误可能被下架 |
| 有内购 / 订阅吗？条款与恢复购买流程齐了吗？ | `CON`：恢复购买路径可执行验证 | 无恢复购买入口直接驳回 |
| 账号删除入口（如平台要求）有吗？ | `CON`：验证方式 = E2E 或人工路径核对 | Apple 等平台强制要求 |

## 产出规则

1. 每个确认项 → 一条 `CON-XXX` 落 01 §6，`类别` 用组名（如 `上架合规` / `发行区域` / `隐私披露`）
2. **优先写可执行验证方式**（脚本 / 命令）。写 `人工` 档必须说明为何不可执行——「后台设置，无本地制品可检」是合法理由，「懒得写脚本」不是
3. 用户答「不清楚」的项 → 进 `needs review` 块，**必填 `归属` / `关闭条件` / `提出`**（见 [SKILL.md § needs review 条目必填字段](../SKILL.md)）；⛔ 不得写成已确认的 `CON`
4. ⛔ **不为凑齐六组而编造 CON**。用户明确说不适用的组，一条不写

> **反向提醒**：本清单是**采集入口**，不是合规保证。平台条款持续变化，且各区域不同。
> `CON` 记录的是「本项目当时确认了什么」，⛔ 不声称「符合平台全部要求」。
