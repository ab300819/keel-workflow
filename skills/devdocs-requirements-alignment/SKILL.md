# 需求对齐检查

验证"各层文档之间是否对齐"——三层对齐检查，防止需求精化过程中的偏移和遗漏。

## 语言规则

- 支持中英文提问
- 统一中文回复
- 使用中文生成报告

## 定位

```
原始需求（用户原话）
    │
    ├─ 层 1：原始需求 → 需求文档（F/US/AC）
    │
    ├─ 层 2：需求文档 → 系统设计
    │
    └─ 层 3：需求文档 → 测试用例
```

每层独立可执行，越早发现偏移，修复成本越低。

## 触发条件

- 需求文档完成后（层 1）
- 系统设计完成后（层 2）
- 测试用例设计完成后（层 3）
- 用户要求检查文档间对齐关系

## 运行模式

```bash
/devdocs-requirements-alignment              → 全部三层检查
/devdocs-requirements-alignment --layer1     → 仅原始需求 → 需求文档
/devdocs-requirements-alignment --layer2     → 仅需求文档 → 系统设计
/devdocs-requirements-alignment --layer3     → 仅需求文档 → 测试用例
/devdocs-requirements-alignment --layer1 --layer2  → 组合检查
```

## 工作流程

```text
1. 确定检查层级
   │
   ▼
2. 读取相关 DevDocs 文档
   ├── 01-requirements.md（原始需求 + F/US/AC）
   ├── 02-system-design.md（设计规范）
   └── 03-test-cases.md（测试用例 + 追溯矩阵）
   │
   ▼
3. 逐层检查
   ├── 层 1：原始需求覆盖矩阵
   ├── 层 2：需求-设计映射表
   └── 层 3：AC-测试覆盖矩阵
   │
   ▼
4. 生成对齐报告
```

## 层 1：原始需求 → 需求文档

### 前提

需求文档中应包含"原始需求"章节（`## 0. 原始需求`），记录用户原话或原始输入。

**兼容性策略**：

| 文档类型 | `## 0. 原始需求` 状态 | 层 1 行为 |
|----------|----------------------|-----------|
| 新建文档（由 `/devdocs-requirements` 生成） | 必须存在 | 正常执行语义对齐检查 |
| 历史文档 / Retrofit 文档 | 可能不存在 | 输出 `⏭️ 前置缺失`，不判定为需求遗漏 |

### 检查步骤

1. 读取 `01-requirements.md`，检查 `## 0. 原始需求` 章节是否存在
2. **若不存在**：层 1 输出 `⏭️ 前置缺失——无原始需求章节，无法执行语义对齐检查`，跳过层 1，继续层 2/3
3. **若存在**：提取关键意图（每条原始需求的核心诉求），逐条检查是否被 F/US/AC 完整捕获

### 检测类型

| 类型 | 含义 | 示例 |
|------|------|------|
| 遗漏 | 原始需求未被任何 F/US/AC 体现 | 用户提到"支持导出"但无对应 F |
| 过度扩展 | F/US/AC 超出原始需求范围 | 用户未提到"多语言"但文档有 F-多语言支持 |
| 偏移 | F/US/AC 语义偏离原始需求 | 用户说"简单搜索"被扩展为"全文检索引擎" |

### 输出

原始需求覆盖矩阵：

```markdown
| 原始需求 | 关键意图 | 对应编号 | 状态 |
|----------|----------|----------|------|
| "用户能用邮箱注册" | 邮箱注册功能 | F-001, US-001, AC-001~003 | ✅ 覆盖 |
| "支持导出 PDF" | PDF 导出 | - | ❌ 遗漏 |
```

## 层 2：需求文档 → 系统设计

### 检查步骤

1. 读取 `01-requirements.md` 中的 F/US 列表
2. 读取 `02-system-design.md` 中的模块/接口/组件定义
3. 逐项检查映射关系

### 检查内容

| 检查项 | 说明 |
|--------|------|
| F → 设计模块 | 每个 F 是否有对应的设计模块或接口 |
| AC → 实现路径 | 每个 AC 是否有接口/组件支撑其实现 |
| 设计孤立项 | 设计中有模块但无对应 F（过度设计风险） |

### 输出

需求-设计映射表：

```markdown
| 编号 | 需求描述 | 设计模块 | 实现路径 | 状态 |
|------|----------|----------|----------|------|
| F-001 | 用户注册 | AuthModule | POST /api/register | ✅ 映射 |
| F-002 | 用户登录 | AuthModule | POST /api/login | ✅ 映射 |
| AC-008 | 连续5次锁定 | - | - | ❌ 缺设计 |
```

## 层 3：需求文档 → 测试用例

### 检查步骤

1. 读取 `01-requirements.md` 中的 AC 列表
2. 读取 `03-test-cases.md` 中的测试用例和追溯矩阵
3. 逐条检查 AC 的测试覆盖

### 检查内容

| 检查项 | 说明 |
|--------|------|
| AC → 测试用例 | 每个 AC 是否有对应测试 |
| 正向路径覆盖 | 测试是否覆盖 AC 的正常场景 |
| 异常路径覆盖 | 测试是否覆盖 AC 的异常/边界场景 |

**复用 devdocs-sync --audit 的孤立编号检测能力**。

### 输出

AC-测试覆盖矩阵：

```markdown
| AC 编号 | AC 描述 | 测试用例 | 正向 | 异常 | 状态 |
|---------|---------|----------|------|------|------|
| AC-001 | 有效邮箱可注册 | UT-001, IT-001 | ✅ | ✅ | ✅ |
| AC-002 | 无效邮箱报错 | UT-002 | ✅ | - | ⚠️ 缺异常 |
| AC-003 | 已存在邮箱报错 | - | - | - | ❌ 无测试 |
```

## 问题分级

### Blocker

- 原始需求遗漏（层 1）
- AC 无设计支撑（层 2）
- AC 无对应测试（层 3）

### Warning

- 原始需求偏移（层 1）
- 过度扩展（层 1）
- 设计孤立项（层 2）
- AC 缺异常路径测试（层 3）

## 输出文件

生成 `docs/devdocs/alignment-report.md`

详细模板参见 [templates/alignment-report.md](templates/alignment-report.md)

## 上下文管理

### 分批原则

按层级分批执行——层 1、层 2、层 3 各为一个自然批次。

### 质量锚点

使用**完备性验证**而非首批锚点：每层检查结束后，核对已报告数量 == 输入编号总数（如层 3 应覆盖所有 AC 编号）。

### 一致性自检

每层检查完成后：
- [ ] 所有输入编号均已出现在输出矩阵中（无遗漏统计）
- [ ] 判定标准一致（同类问题同等判定）

## 约束

### 检查约束

- [ ] **必须读取所有相关文档后再检查**
- [ ] **层 1 依赖"原始需求"章节——新文档必须存在，历史文档若不存在则输出"前置缺失"并跳过层 1**
- [ ] **每层检查必须覆盖所有编号，不遗漏**
- [ ] **检查结果必须生成矩阵，不仅文字描述**

### 安全约束

- [ ] **不修改任何文档，只生成报告**
- [ ] 发现问题时建议修复路由，而非直接修改

### 上下文管理约束

- [ ] 每层检查后验证编号完备性（报告条目数 == 输入编号数）
- [ ] 判定标准跨层一致

## Skill 协作

| 场景 | 协作 Skill | 说明 |
|------|-----------|------|
| 需求完成 | `/devdocs-requirements` | 被调用：需求扩写后触发层 1 |
| 设计完成 | `/devdocs-system-design` | 被调用：设计完成后触发层 2 |
| 测试设计完成 | `/devdocs-test-cases` | 被调用：测试设计后触发层 3 |
| 追溯检查 | `/devdocs-sync --audit` | 复用：孤立编号检测 |
| 追溯扫描 | `/devdocs-sync --trace` | 复用：标注扫描能力 |
| 需求补充 | `/devdocs-requirements --incremental` | 路由：发现遗漏时 |
| 设计补充 | `/devdocs-system-design` | 路由：发现设计缺失时 |
| 测试补充 | `/devdocs-test-cases` | 路由：发现测试缺失时 |

## 下一步

| 检查层 | 结果 | 建议下一步 |
|--------|------|------------|
| 层 1 有遗漏 | Blocker | `/devdocs-requirements --incremental` 补充 F/US/AC |

| 层 3 有缺失 | Blocker | `/devdocs-test-cases` 补充测试用例 |
