# 任务归档功能

## 归档触发条件

同步时自动检测以下条件：
- `04-dev-tasks.md` 超过 **300 行**
- 已完成任务超过 **15 个**

满足条件时，在偏差报告中提示：
```
⚠️ 建议归档：已完成任务 18 个，超过阈值 15 个
是否将已完成任务归档？[是/否]
```

## 归档规则

**主文档保留**：
- 所有"待开发"和"进行中"任务
- 最近完成的 **5 个任务**

**归档文件**：`04-dev-tasks-archive.md`

**归档结构**：按功能点 (F-XXX) 分组

```markdown
# 已完成任务归档

## F-001: 用户注册

### T-01: 数据库表设计 ✅
- **完成时间**：2024-01-15
- **关联需求**：F-001, AC-001
- **涉及文件**：`src/db/schema.ts`
- **测试结果**：IT-001 通过

---

## F-002: 用户登录
...
```

## 归档流程

```
1. 检测归档条件
   │
   ├── 未满足 → 正常同步
   │
   └── 满足 → 询问用户
         │
         ├── 拒绝 → 正常同步
         │
         └── 确认
               │
               ▼
2. 识别待归档任务
   ├── 已完成且不在"最近5个"内
   └── 按关联功能点 (F-XXX) 分组
         │
         ▼
3. 更新归档文件
   ├── 追加到对应功能点分组
   └── 按完成时间排序
         │
         ▼
4. 更新主文档
   ├── 移除已归档任务详情
   ├── 保留执行检查清单
   └── 添加归档引用链接
```

## 操作命令

```bash
# 由 /devdocs-sync 自动建议
/devdocs-sync
# → 检测到已完成任务过多，是否归档？

# 或手动触发
/devdocs-sync --archive
```
